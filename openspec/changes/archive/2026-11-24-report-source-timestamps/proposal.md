# Proposal（草案，待决策后补 design / specs / tasks）

## Why

**要回答的问题：**读一份首席决策或分析师日报时，我能不能一眼看出"这个结论靠的是哪几条信息、每条信息是哪天的"？

目前不能。

- **首席决策：**
  - 引用只有投影 ID 的前 8 位（如 `321c9ec8`）。读者看不出它指向哪位分析师、哪份结论、是几天前的。
  - 「证据权衡」表把引用整列丢掉了（`src/ats/agents/chief/report.py:30, 75-77`）。
  - 喂给首席的上下文里，单条投影只标了 ID 和哈希，**没有 `as_of`**；只有类别标题行有"最新 @ 时间"（`src/ats/agents/chief/assemble.py:727-730, 801-805`）。
  - 例：11-18 那份决策用到的层分析和宏观分析已是 4 天前的，但只能从类别标题行看出来。
- **分析师日报：**
  - 层分析的判读行只有说话人、维度、理由，没有文档、发布日期、观测 ID（`src/ats/agents/sector/report.py:279-285`）。
  - 基本面的「依据/来源」是自由文本。
  - 宏观指标表已有「截至」列和过期标记，是现成的好样板（`src/ats/agents/macro/report.py:177-181`）。
- **底层时间戳不对：**
  - 产业链观测的 `observed_at` 写的是**抽取时间**，不是信息本身的时间（`src/ats/agents/evidence/observer.py:392`）。
  - 文档的发布时间（`published_at`）、采集时间（`fetched_at`）在入库模型上是有的，只是没传到观测和报告。

## What Changes

**原则：引用上的时间戳由代码从库里查出来写进报告，不让模型自己写日期。**这样模型无法编造日期，口径也统一。

1. **引用格式统一为"来源 · 信息时间 · 距决策时长"。**
   - 首席示例：`层分析·L5芯片设计 · 截至 11-14 01:30 · 4.5 天前`。
   - 日报示例：`ORCL 10-Q · 发布 11-12 · 采集 11-12 22:30`。
   - 超过该任务新鲜度窗口的引用（窗口见 `src/ats/workflow/planning.py:66-80`）加 ⚠️。
2. **首席决策报告：**
   - 引用列展开为上面的格式。
   - 「证据权衡」表恢复引用列。
   - 文末新增「依据清单」，逐条列出：被引用的分析师结论 → 它的 `as_of` → 它直接依赖的数据源与最新数据时间。
3. **首席上下文：**每条投影行补 `as_of` 和距今时长，让首席在下判断时就知道信息新旧。
   - 只改 chief 的上下文拼装，不动 `agents/base.py`。
   - 首席的提示缓存会失效一次。
   - 不增加请求数。
4. **分析师日报：**
   - 层分析的判读行补「来源文档 · 发布日期」。
   - 基本面的依据列改为结构化的「来源 · 期末 · 发布」。
   - 宏观日报保持现状。
5. **信息时间在渲染时联表求出，不改表、不回填。**
   - 新报告会引用很早以前抽取的观测（层分析汇总多期证据），所以不能只给"新抽取的观测"带时间。
   - 改法：渲染时用 `document_id` 联 `data_documents`，按以下顺序取第一个可用的时间：
     1. 文档 `published_at`（标"发布"）；
     2. 文档 `fetched_at`（标"采集"，并注明发布时间未登记）；
     3. 文档 ID 里带的日期（标"文档日期"）。
   - 能解析成日期的数据期（如 `2026-04`）在旁边另外注明"数据期"，不顶替信息时间。
   - 2026-11-19 实施时修订：原稿把"期间"排在采集时间之前。实测发现文章观测的"期间"常是预测区间（如 `2022-2028`），不能当发布时间用。
   - 保留 `observed_at` 原义（抽取时间），不再拿它当信息时间。
   - 2026-11-19 实测，10,686 条现行观测中：
     - 6,600 条能联到文档，其中 4,904 条有发布时间；
     - 其余可用期间或采集时间兜底。
6. **修首席上下文里的截断 ID。**类别标题行把投影 ID 截成 18 位（`assemble.py:730`），首席照抄后，审计记为"不存在的 ID"。
   - 改为不在标题行出现 ID；投影 ID 只在逐条投影行完整出现一次。

## 已定（2026-11-19）

- **D1：**主显示"信息时间 + 距今多久"，采集时间只放依据清单。
- **D2：**首席引用了不存在的 ID 时**不拦截**，只在报告里标红。
  - 已查明的两类成因：
    - 11-16：首席照抄了标题行里截断成 18 位的 ID，投影本身存在。由第 6 项修掉。
    - 11-06：一个全 32 位、但库里查不到的 ID，属模型编造。
- **D3：**不回填，历史报告不重做。新报告靠第 5 项的渲染时联表拿到旧观测的时间。
