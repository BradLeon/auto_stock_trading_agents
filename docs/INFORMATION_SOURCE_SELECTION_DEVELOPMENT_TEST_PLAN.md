## 1. 依据与范围

依据 [TARGET_WORKFLOW_DATAFLOW.md §9.1](TARGET_WORKFLOW_DATAFLOW.md#91-information-analyst) 及其数据与角色边界：

- Data Platform 负责外部采集、文档准入、不可变版本及中性关联元数据。
- Information 只读取准入材料，负责正文抽取、相关性和材料性判断；结论保留文档版本、片段位置、时间及置信度。
- Fundamental 负责自己的业绩预期、核心叙事和投资解释。Information 不读取其观点来生成检索条件。
- 复用已有配置、Information 抽取、triage、处理账本与 Task Projection，不新增 Agent 或 workflow，不绕过 scope、owner、准入或采集队列。

当前拟实施范围：正文预算与分配、公司实体关联、研究通讯候选接入、可见预览的准确消费。动态图谱、投资叙事驱动检索、全量语义事实库、自动判断所有历史事实的新颖性均后置。七天窗口不因本实验自动取消；历史背景不能包装成今日新消息。

## 3. 开发方案

### 3.1 预算及选择顺序

保持“发现标题 → 候选处理 → 取正文 → 准入”的数据平台流程：

- 先复用原生 ID、规范 URL、同标题同精确时间等确定性去重，再占用正文请求。相似标题不自动证明重复，同一事件的新版本不能误删。
- 已明确不满足当前实体准入策略的标题，不优先耗尽主要正文预算；记录丢弃／延期原因。标题无法关联但可能包含间接事实的材料进入有限探索队列，不放宽正式正文准入。
- 为所选标的保留基本请求机会；剩余额度共享。多标的材料只请求一次正文。实现时区分直接公司标题与泛行业标题，避免统一最新排序垄断预算。
- 重复刷新优先复用已存在且完整性适用的正文，给未处理候选续取机会；保留来源版本更新检查，不能永久停止检查已缓存文章。
- 初始实验预算候选为每轮 24～32 次，正式值待 E4 测量确定，不在本文自动修改 10 次生产配置。采用请求上限和总耗时上限双约束；失败重试计入预算。

记录发现数、初筛数、缓存命中数、实际请求／重试数、准入数、延期数及各标的覆盖。预算只控制数据获取，不授予模型、交易或其他 source 权限。

### 3.2 中性实体关联

保留出版者身份，补充 related_entities，不把出版者直接替换成目标公司。

- 标题：复用公司名、ticker、已登记别名，匹配完整允许集合；查询合约仅为查询血缘，不能作为正文与公司的关联证明。
- 正文：对实际取得的文本做确定性实体识别，保留支持的段落／字符范围与关联方法。仅有关键词、模糊简称或一次提及不能自动产生高重要性结论。
- 无 ticker 的行业主题：先作为来源限定的候选通道处理，不新增动态产业图谱。由 Information 在有限预算内解释实际正文与现有 signal_chain 的关系；观点只进 Workflow Memory。
- Data Platform 的关联索引用于可发现性；Information 的相关性／影响解释用于分析。模型产生的影响推断不能直接冒充共享中性事实或写回来源实体索引。
- 已存在同正文文档仍需可重建关联。不得因正文 no_change 跳过元数据修复；新增关联发布保留 known_at，旧 as_of 读取仍看到旧索引。文档正文版本与关联版本分别表达，不为关联更新伪造新正文。

先使用已有静态 signal_chain 和别名配置，不维护公司叙事／估值驱动的动态 mapping。

### 3.3 来源分级筛选与 Information 接入

| 来源 | 候选策略 | 正文及标的关联 |
|---|---|---|
| SemiAnalysis IMAP/RSS | 已登记发件人／publisher 作为来源通道；标题无 ticker 不能成为直接丢弃理由 | 在独立有限预算中处理未抽取版本，允许无相关 insight 的合法结果 |
| TrendForce 网页 | 用标题公司／产品／行业关键词做低成本初筛，保留行业探索额度 | 对公开可读正文建立中性关联，再做 Information 材料性筛选 |
| IBKR | 合约查询、标题实体及通用关键词组合 | 主预算优先有效候选，探索额度覆盖标题遗漏的可能关联 |

来源声誉只影响候选路由，不能代替事实可信度。TrendForce 当前是网页源，不假设存在其订阅邮箱接入或受许可研究库访问。

处理顺序：来源／版本检查 → 标题与已有摘要初筛 → 有限正文抽取 → 标的相关性与材料性 → 简报。已有抽取结果按文档版本和处理器版本复用。

接入 `agents/information/extract.py`、`triage.py`、`assemble.py` 和 `entry.py`，先核对当前角色及读取契约：

- 不能通过取消 bound-task scope 来恢复全库读取。抽取要在授权范围内运行，或复用已有独立抽取入口及其合法 scope；不新建额外 Agent/workflow。
- 出版者限定的探索候选也必须通过 Data Products 的显式 scope；消费者不能直接扫库、邮箱或 provider。具体 scope 扩展须写入适用契约和受影响清单。
- 旧 triage 的 thesis 参数不能直接接入 Fundamental 观点；使用中性业务背景或调整该角色内的接口。
- 现有抽取投影按文档组织，而标的简报按标的组织；明确合法消费、缓存复用、去重及血缘，不能假设运行抽取就会自动补齐目标简报。
- 初轮复用当前每轮 8 篇抽取、每篇 40,000 字符配置作为测量起点，不同时无界放大采集预算和模型预算。总字符／token 预算与延迟上限在真实取证前登记。
- 新输入范围不得只查最近两天而遗漏未处理材料：按来源发布时间、未处理版本与原 as_of 选择，记录回补和背景；不把旧材料重新标成新发布。

### 3.4 全文、预览与标题

| 状态 | 消费政策 |
|---|---|
| 全文 | 正常抽取；保留来源性质和时间，不把作者预测当 actuals |
| 实质预览 partial | 仅从可见片段抽取，明确全文未取得及截断原因；不得推断隐藏内容 |
| 仅标题／订阅提示 teaser | 保留为待取得证据的候选，不作为已证实事实输入 |
| 正文解析失败／访问失败 | 记录 acquisition gap，与订阅限制、无相关新闻分列 |

现有 SemiAnalysis 的 2,000 字符分类／准入规则应统一评估。不能仅因短而拒绝有实质内容的预览，也不能仅因长而认为完整。若允许短预览，须增加显式内容类型和有效正文检查；不能笼统降低所有 source 的 minimum_body_chars。

第一批保留 TrendForce “公开正文”政策；不新增付费研究产品接入。需要预览支持时另行登记该 source 的可见内容准入和消费策略，不能套用 SemiAnalysis 的许可。

模型上下文逐文档传递 completeness、可见长度、输入截断、版本及定位；报告同步呈现。文档全文可读但模型只接收截断正文时，应同时标记两种状态。无权限不能通过生成、拼接营销段落或补写正文来冒充取得全文。

以后获取更完整内容，应保存完整版本及新的 known_at，保留预览版本和既有引用。更完整不自动代表更新发布事件，旧报告不改写。

## 5. 测试与验收

### 5.1 无网络回归

| 编号 | 情景 | 预期 |
|---|---|---|
| T1 | 大量最新泛新闻加较早直接 MRVL 候选 | 在指定配额内直接候选获得机会，总请求不超预算；不以“全取到”为要求 |

| T3 | 查询合约与文章实体不同、别名／正文提及／歧义简称 | 查询血缘不冒充关联；明确实体有定位，歧义不强关联 |
| T4 | 同正文、后来补关联 | 当前 scope 可发现，旧 as_of 不变；不创建虚假的新正文版本 |
| T5 | SemiAnalysis 无 ticker 标题及完全无关文章 | 前者可进入有限来源通道，后者可返回空 insight；不把 publisher 当重要性结论 |
| T6 | TrendForce 标题／正文涉及 MSFT、NVDA、TSM | 准入后可被合适 scope 发现，仍由 Information 判断价值；观点不写入共享事实 |
| T7 | 实质 partial、营销 teaser、全文、解析失败 | 按政策分别处理，输出披露可见范围，不臆测缺失内容 |
| T8 | preview 后取得完整版本、模型输入截断 | 旧引用可解析，新版本有独立 known_at；文档完整性与模型可见性分别标记 |

### 5.2 实际采集与模型验证

1. 保存刷新前输入与版本，固定四标的 scope。IBKR 在本机运行，只读新闻 API；采集走队列，production owner 不变。
2. 使用一个共同评估时点比较刷新前后，分别报告七天消息与历史背景。新增材料不得回填旧报告的 as_of。
3. 输出每 ticker 的候选、选择／拒绝原因、标题、正文概览、版本、完整性及来源；记录请求／重试、缓存、准入率、各 ticker 覆盖、用时。
4. 重新验证 MRVL XPU Attach 候选是否获得正文，以及明显的 Microsoft／Nvidia／TSMC 行业文章是否能被合法 scope 发现。正文无权限或质量不达标时保留缺口，不强制准入。
5. 先完成无模型选择验收，再在适用授权内做有限真实 Information capture。新 newsletter 正文、扩大的历史输入或改变外发内容不能自动沿用原八 scope 的 OpenRouter 内容授权。
6. 接通 Routine 时只重验受影响的依赖和断言。旧新报告都保留，记录新输入及实现指纹；本计划通过不代表生产 assurance 完整、部署获准或真实下单获准。

通过条件是预算受控、直接材料不被不合理地遮蔽、关联有依据、预览消费准确、scope／历史血缘不破坏。不同日期的自然新闻数量不能作为固定阈值；没有重要消息时不要求凑数。耗时／成本阈值在 E0 的试验记录中填写并于调用前确认，未测量前不能宣称达到性能目标。
