## Context

动机见 `proposal.md — Why`；行为契约见 `specs/sector/chain-layers/spec.md` 与
`specs/sector/layer-analyst/spec.md`。这里只记约束与技术取舍。

**现状里必须先看清的四件事：**

1. **层键是数据，不是代码。** `grep` 全仓：`L1_app`…`L6_equipment` 只出现在 `config/`、
   `tests/` 和 `docs/` 里，`src/` 中**零处硬编码**。所以重排层结构的成本几乎全在
   ①配置搬迁 ②sqlite 历史 ③文档，代码改动集中在新增能力而不是改造旧路径。
2. **`layer_cap` 是权重的唯一入口。** `cross_section.rank_cohort(layer_cap=)` 用 softmax ×
   1/beta × 流动性折价把 `layer_cap` 分配下去；`layer_cap` 来自 `layer.weight_cap`，
   而后者由 `config.py` 从 `risk.yaml` 的 `sector_layer_caps` 注入。**这是绑定配置结论的
   唯一接线点**，不需要新的权重通道。
3. **风控用的是同一个 `weight_cap`。** `risk/assess.py:478` 用 `ly.weight_cap` 做层集中度
   breach 检查。它必须继续读**静态**上限——否则「低配」会把既有持仓瞬间判成超限。
4. **已有一条 layer_view 依赖。** 现在的顺序是「整行业评审 → 逐层截面 + 结构分析师
   （吃当轮 layer_view）」。引入层级分析师会改变这个顺序，必须给结构分析师重新安排上下文。
5. **结构因子只吃 relative 命题。** `chain/factor_evidence.py:115` 一行写死：
   `if claim.kind != "relative" or a.verdict != "resolved": continue`。common 命题目前只进
   行业分析师的「供需」块。这条既有分工是 D15 的起点，不是本次新发明的。
6. **宏观已有两个落点。** `assemble.py:116` 注入行业分析师，`chief/assemble.py:54` 注入 Chief。
   同一个因素被两处消费——见 D16。

**术语**（这三个词在下文反复出现，先钉死）：

- **定价机制**：这家公司的单位价格由什么决定、它能不能自己定。见 D1 的四类表。
- **z 分**（`cross_section._zscores`）：把一层内所有公司的某个指标减去该层均值、除以标准差，
  得到可加的标准分；复合成 composite → 排名 → softmax 转权重。**它是相对的**——只说
  「在这层里排第几」，不说绝对好坏。所以同层必须可比，否则它度量的是分组差异不是公司差异。
  样本 <2 时全返 0。
- **subgroup**（`LayerTicker.subgroup`）：层内的字符串标签。两个用途：`structure_notes`
  按它挂知识库笔记；结构分析师按它输出 `tech_curve_note`（如「光进铜退」）。
  **它不参与 z 分计算**（见 D3）。现状只有 `L3_dc_infra` 在用；新方案里 L4 互联继承原有的
  三个、L6 存储新设四个、其余六层不设。

## Goals / Non-Goals

**Goals**
- 层的三重职责（传导位置 / 截面 cohort / 风险簇）在 `ai_hardware` 上同时成立
- 层级配置结论有仓位落点，且**永不放松**既有护栏
- 层键更名后历史可解析、不改写旧行
- 保留 `kb_perturb`（知识库消融检验）这件仪器的可用性
- 每个分析师只回答自己那一层的问题：产业链问产业证据，宏观留给宏观分析师（D16）

**Non-Goals**
- 不改截面因子权重、不改 softmax/beta/流动性折价的定权算法
- 不改证据引擎（三道闸、去重、立场加权）的任何规则
- 不引入自动交易；清仓仍是提案，仍走人工审批
- 不为新增标的建 PEAD 活体档案（那是独立决策，每家都是持续成本）

## Decisions

### D1 — 拆层的判据是「定价机制」，不是「产业环节」

**这条反直觉，所以先说清楚它在回答什么。** 产业环节（设计→制造→封测→设备）是教科书切法，
它回答「这东西是怎么做出来的」。但层要回答的是三个操作问题：这两家放一起比 PEG/毛利率有没有
意义（②）、它们同时跌的概率有多大（③）、给这一组一个共同上限限住的是不是同一种风险（③）。
**产业环节不回答其中任何一个。**

**定价机制 = 这家公司的单位价格由什么决定、它能不能自己定。** 这条链上有四种：

| 机制 | 价格由谁定 | 典型 | 财务特征 |
|---|---|---|---|
| 产能垄断型服务 | 卖方（唯一供给） | TSM 先进制程 | 毛利高且稳，靠节点涨价 |
| 商品化周期品 | 供需（bit 现货价） | DRAM / NAND / HDD | 毛利大幅摆动 |
| 技术代际替代 | 新一代的溢价窗口 | 光模块 1.6T / CPO | 毛利随代际起落，打份额战 |
| 机电装机量 | 项目招标 / 长单 | VRT / ETN / GEV | 毛利平稳，靠量 |

**最能说明问题的是反例**：TSM 与美光的毛利率差**不来自谁经营得更好**，来自商业模式。
而 z 分会把这个差读成「TSM 的质量因子更强」——一个每周都会出现的假信号。按环节切必然把这两种
机制装进「制造」一层。风险簇同理：商品化周期品一起涨跌（吃 bit 周期），产能垄断型不跟它们同步，
而 cap 要限住的正是「一起跌」。

**被否决的替代**：保持 6 层、用 subgroup 承担 cohort。否决理由是 ③ 解决不了——
`weight_cap` 与 breach 检查都是层级的，subgroup 再细也共用一个相关簇上限。

### D2 — 拆「互联与网络」而不是只拆「光互联」

光 / 铜 / CPO / 交换是**互相替代**的同一个战场。放同一层，relative 命题才有对手可比；
拆成两层则每层都变成单一子层，回到 L1 的单样本困境。

副产品：`AVGO` 的交换芯片收入与 `MRVL` 的光 DSP 收入现在被 L4 命题注释**显式排除**、
又不属于 L3 任何命题——两笔收入无家可归。新结构下二者以 `cohort_extra` 参与互联层排序
（风险归属仍在芯片设计层），沿用 `MRVL` 已经在用的机制。

### D3 — 层 = 风险预算与景气单元；subgroup = 叙述与比较的分组标签

存储层内 HBM / 常规DRAM / NAND / HDD 的**股价同吃存储周期 beta**（③ 成立），但产线与工艺
不同（② 只在 subgroup 内成立）。所以：

- 层级：一个 `weight_cap`、一条配置结论、一个相关簇
- subgroup：**叙述与比较的分组标签**——层级分析师写「买谁」时先在组内比、再跨组说明本期偏向

**z 分的作用域是层，不是 subgroup**（2026-08-20 用户裁定）。存储层的 z 分在**层内统一计算**，
subgroup 不参与标准化。理由是 subgroup 内样本太小（HDD 两只、NAND 一只），组内标准化会让
z 分主要反映组内排名而不是层内位置，且单样本组恒为 0——那正是 `_zscores` 在样本 <2 时的退化。
**代价要承认**：HDD 与 HBM 的毛利率/增速分布不同，层内 z 分会把这个分布差异读成公司间差异。
处理办法不是改标准化口径，而是靠层级分析师在叙述里按 subgroup 分开讲（spec 已要求）。

**已知的脏边界**：美光同时做 HBM/DRAM/NAND，subgroup 按**主导驱动**归为 HBM，在 `note`
里写明它的 NAND 敞口。这是有意的近似：subgroup 是比较用的标签，不是收入拆分。

### D4 — 层键重新编号 L1..L8，历史靠 `legacy_keys` 解析

`SectorLayer` 新增 `legacy_keys: list[str]`。读历史（`claim_assessments.layer`、
`sector_reviews` 的 `LayerAssessment.key`）时把历史键解析到声明它的当前层；**旧行一律不改写**。

拆分产生一对多：`L5_fab` 同时被 `L6_memory` 与 `L7_foundry_pkg` 声明。两层查历史都能看到那段
记录，展示时标注「拆分前的合并口径」。

**为什么不改写旧行**：旧行记录的是**当时的判断口径**。把 `L5_fab` 的一条结论改写成
`L6_memory`，等于声称当时那条结论是在存储的独立口径下做出的——那是伪造历史。

**被否决的替代**：去掉序号改语义键（`memory` / `foundry_pkg`）。迁移量与本方案相同，
但序号在提示词里承担了「需求沿 L1→Ln 传导」的语义，去掉会让 LLM 失去传导顺序的线索。

### D5 — 层级配置结论 → 预算使用率 → `layer_cap`

```
basket 权重之和 = weight_cap × clamp(utilization(verdict), 0, 1)
```

`utilization` 映射表写在 `risk.yaml`（默认 超配 1.0 / 标配 0.6 / 低配 0.3 / 清仓 0.0）。

**为什么映射表在配置、结论在模型**：映射表是**治理**（这个账户愿意让一条判断把预算摆动多大），
判断是**语义**（本层现在是什么位置）。把判断写成 YAML 标量会让它失去证据与留痕；把治理写进
提示词会让它随模型漂移。结论连同 confidence 与逐条议题归因一起落库，可回溯。

**钳制在代码里做**：即便配置把使用率误设为 1.5，代码也钳到 1.0。

### D6 — 护栏检查用静态 cap，预算分配用调整后的 cap

`risk/assess.py` 的层集中度 breach **继续读 `layer.weight_cap`**（静态上限）；
只有 `cross_section` 读使用率调整后的值。

**为什么**：使用率是「新增资金愿意投多少」，breach 是「已有持仓是否越界」。若两者共用一个数，
一条「低配」结论会把满仓但合规的层瞬间判成超限、触发不必要的减仓——这是**用建议信号冒充
风险事件**。

### D7 — 拆层不得放大总敞口：新增 `layer_group` 上限

拆层有一个机械性副作用：`L5_fab ≤30%` 变成两个各自独立的 cap，两层同时满仓就能到
`25% + 20% = 45%`。**这等于在重构的掩护下悄悄放松了护栏。**

方案是**加一层新护栏而不是撤销旧的**：`risk.yaml` 新增 `layer_groups`，把拆分出来的子层
重新绑成一个上限，数值取拆分前的原值。

| group | 成员 | group cap | 说明 |
|---|---|---|---|
| `dc_infra` | L3 电力冷却 · L4 互联与网络 | 0.15（hard 0.20） | 沿用原 `L3_dc_infra` |
| `fab_memory` | L6 存储 · L7 代工与先进封装 | 0.30 | 沿用原 `L5_fab` |

子层 cap 建议值（子层之和 > group cap 是**有意的**：允许配置在两者间倾斜，但合计仍被 group 卡住）：

| 层 | weight_cap | 来源 |
|---|---|---|
| L1 应用 | 0.15 | 不变 |
| L2 云服务 | 0.25 | 不变 |
| L3 电力与冷却 | 0.10 | 新，受 `dc_infra` group 约束 |
| L4 互联与网络 | 0.15（hard 0.20） | 继承原 L3 的敞口性质 |
| L5 芯片设计 | 0.15 | 原 L4，不变 |
| L6 存储 | 0.25 | 新，受 `fab_memory` group 约束 |
| L7 代工与先进封装 | 0.20 | 新，同上 |
| L8 半导体设备 | 0.15 | 原 L6，不变 |

group 上限同时在 `risk/assess.py` 里成为一条新的 breach 检查。

### D8 — 流水线顺序：量化截面 → 结构分析师 → 层级分析师 → 跨层轮动

```
每层并行：
  ① fetch_factors + rank_cohort   纯代码 ────────────────→ 量化 basket
  ② structure.assess              KB + relative 读数 ────→ tech_tenor/moat_pricing → 混合重排
  ③ layer_review.run              common 结论（该给多少钱）
                                  relative 读数（选谁）
                                  判据笔记 + 混合 basket
                                  上一轮本层 verdict ────→ LayerVerdict
                                                          └→ utilization → 重算权重（排名不变）
全部层完成后：
  ④ sector rotation               8 条 LayerVerdict ─────→ 轮动建议 + 一致性检查

※ 三个阶段都不吃宏观（D16）；② 不吃 common，③ 的两类证据分开定向（D15）
```

**为什么不把结构分析师合并进层级分析师**（上下文高度重叠、能省 8 次调用）：
`ats sector kbperturb` 这件仪器专门检验「知识库是否真的在起作用」，它依赖结构打分是一个
**可单独消融的阶段**。合并会让这个检验失去对照组。确定性因子打分与叙事判断分开，也让
`feeds_factor` 的语义保持干净。

**代价与处理**：结构分析师现在吃的 `layer_view` 来自同一轮的整行业评审；新顺序下层级结论在它
**之后**产出，所以改吃**上一轮**的该层 LayerVerdict。周度节奏下，上一轮结论是合法的先验；
在提示词里明确标注它是上一轮的，避免被当成本期结论。

**为什么保留跨层轮动这一步**：`docs/SECTOR_ANALYST.md` 记着「层间轮动本质是跨层比较，
必须在同一上下文里完成」——这条仍然成立，只是它现在比较的是 8 条紧凑结论而不是全部原始素材。

### D9 — 失败与降级

- 单层评审失败 → 回退到该层上一次的 LayerVerdict；没有上一次则用保守默认使用率（标配），
  **不落库**，不中止其余层
- 样本 <2 的层（`_zscores` 全返 0）→ 跳过 basket，只出层级结论并标注「截面不适用」
- 轮动阶段失败 → 保留各层 LayerVerdict（它们已各自落库），周报缺轮动段

### D10 — 宇宙扩容名单

共 6 只（2026-08-20 用户定稿）：

| 层 | 新增 | subgroup | 理由 |
|---|---|---|---|
| L6 存储 | SNDK | NAND | 2025 年从西部数据分拆，纯 NAND |
| L6 存储 | STX / WDC | HDD | 近线 HDD 的两家；AI 存储外溢的直接承接方 |
| L3 电力与冷却 | ETN | —（本层不分组） | 数据中心配电 |
| L3 电力与冷却 | GEV | —（本层不分组） | 燃气轮机/电网，供电瓶颈的直接受益方 |
| L3 电力与冷却 | BE | —（本层不分组） | 现场发电（固体氧化物燃料电池），绕过电网接入排队 |

**BE 是本层纯度最高的一只，也是最不同类的一只。** 它卖的是 behind-the-meter 现场发电，
而电网接入排队正是「供电瓶颈」叙事里最硬的那条约束——所以它的 AI 数据中心敞口比
ETN/GEV 高。但它的定价机制是**技术采纳曲线**，ETN/GEV 是**机电装机量**，这正是 D1 要防的混装。
它仍然入本层，因为 ③（同吃「数据中心供电瓶颈」这个 beta）成立，而单拆一层会回到单票困境。

**电力层不设 subgroup**（2026-08-20 用户裁定）：四只票分组是过度设计。**代价记在这里**：
层级分析师写「买谁」时没有现成的分组语言，BE 与 ETN 会被放在同一张 z 分表里直接比——而它们的
毛利率/PEG 分布本就不同。对冲办法只有两个，都在配置 `note` 里：写明各自的敞口性质与定价机制，
让分析师在叙述层自行区分。若跑两轮后发现 BE 的 z 分持续被非同类因子主导，再考虑补分组。

**纯度警告（必须写进配置 note）**：ETN/GEV/STX/WDC 的 AI 数据中心敞口都**不是 100%**，
它们的 z 分里混着非 AI 业务。这不影响相关簇（③ 仍成立），但会稀释截面比较（②）。
处理办法是在 `note` 里写明敞口性质，并在命题的 `expect_from` 上保守——**不为它们声明
它们答不上的维度**（沿用本仓已有的纪律：声明一个说不出区分度的证人只会把覆盖率的分母做大）。

`PWR`（Quanta，电力施工）暂不入表：它是工程承包，定价机制与设备制造不同，进来会重犯
D1 要解决的毛病。

### D11 — 配置搬迁靠机械校验，不靠肉眼

`ai_hardware.yaml` 有 1980 行，其中绝大部分是命题、证人表与**记录判断理由的注释**——
那些注释是这个仓库最贵的资产（多处写着「记下来免得重犯」）。搬迁必须**整块原样移动**。

验收靠一个一次性脚本对比搬迁前后的不变量，而不是靠阅读：

- 全部 `claim.id` 集合不变
- 每条命题的 `concepts[].key` 与 `expect_from` 不变
- 每条命题的 `witnesses` 集合不变
- 每层 `tickers` 的并集 = 原并集 + 本次新增的 6 只（SNDK / STX / WDC / ETN / GEV / BE）
- `structure_notes` 引用的文件路径全部存在
- **每只原有票的 `concept_menu` 键集合不变**——这一条直接盯住 D13 要防的失效模式：
  搬迁若碰坏了某条命题的证人声明，症状不是报错，是那家公司的观测**静默地**全部未映射。
  ⚠️ **不能要求「非空」**：2026-08-20 实测基线显示 `VRT` / `AAOI` / `AXT` 与两个 SK 别名代码
  （`HY9H` / `000660.KS`）本来就是空菜单。所以通过条件是「不变」，「本来就空」的单独列出来
  提醒——这批票的缺口比 D13 原先估计的更大，见任务 5.1。

### D12 — 命题挂「被判断的主体」所在层，证人表天然跨层

拆层立刻会遇到一条命题的**主要发声方在另一层**：`hbm_supply_tight` 的 `packaging_throughput`
维度（先进封装产能、排期、是否成为出货瓶颈）主证人是 TSM，而 TSM 拆分后在 L7。

**规则**：命题挂在它**判断的对象**所在层，不挂在**说话的人**所在层。所以
`hbm_supply_tight` 整条留在 L6 存储——它判断的是 HBM 供给，封装吞吐只是这条供给链路上
的一环（配置注释已写明「HBM 装到加速卡上必须过 CoWoS 这一关」）。

推论：**`witness_roster` 不随拆层改动**。它本来就跨层——`upstream: [ASML, KLAC, LRCX, TSM]`
在拆分前也不是同层公司。把它按新层重切是错的：那会把「谁能作证」偷换成「谁在同一层」。

写死这条规则是为了**下次拆层不用重吵**。没有它，每次层结构变动都要重新讨论几十条命题的归属。

### D13 — 新层与新票的命题缺口：先观测，再声明（两步法）

拆完之后 **L3 电力与冷却层零命题**：现有 `L3_dc_infra` 的四条命题
（`optical_component_supply_gap` / `rate_transition_pricing_power` / `copper_ip_crosses_to_optical` /
`interconnect_moat_distribution`）**全部是互联的**，整块去 L4。同理，六只新票不在任何命题的
`expect_from` / `witnesses` / `entities` 里。

**后果是静默的**：`observer.concept_menu` 按「这家公司是不是某条命题的声明证人」过滤，
声明为空 → 菜单为空 → `extract` 把它的观测 concept 全部置空 → 100% 未映射。
**这个坑本仓踩过一次**：2026-08-14 之前 L3 一条命题都没有，COHR 216 条、LITE 52 条读数
全部落在未映射池，配置注释写着「证据一直在库里，只是没有落点——**这是配置缺口不是数据缺口**」。

**两个方向相反的毛病，判据是同一个**：

| 毛病 | 症状 | 触发条件 |
|---|---|---|
| 造沉默证人 | 覆盖率分母变大，看起来更差而并没有更差 | 声明了**拿不到文档或说不出区分度**的证人 |
| 读数无处可落 | 观测 100% 未映射，看起来没数据而其实有 | 该实体**已在产出读数**却没被任何命题声明 |

所以判据不是「声明还是不声明」，而是**这个实体是否已经在产出读数**。这就要求先观测。
本仓已有正确先例：TRENDFORCE「首轮抓取实测产出 57 条读数、全部落在未映射池——**声明即是为了
让那批读数有地方落**」。

**本次变更的做法**（2026-08-20 用户裁定）：

1. 电力层 `claims: []` **显式留空**，注释写明原因与下一步，而不是留个空位假装没这回事
2. 新增任务：跑一轮 observe，导出这六只票 + 电力层四只票的**未映射池清单**（它们实际说了什么）
3. 层级分析师对无命题的层显式标注「本层无命题，结论仅来自快照与判据笔记」
4. 下一轮拿真实读数起草命题——维度由读数决定，不是先设计维度再指望它答得上

### D14 — 证据块按层切分

`assess_layer` 本来就是按层跑的；问题在汇总：`assemble._chain_evidence` 把**全 sector** 的
结论汇成两个大块（供需 ← common、定价权 ← relative）塞给单一的行业分析师。

层级分析师要的是**只含本层**的两个块。改造点因此在汇总函数，不在证据引擎——引擎的三道闸、
去重、立场加权一行不动（Non-Goals 已声明）。

跨层轮动阶段**不再收原始证据块**，只收各层 LayerVerdict 里的议题归因。这也是调用数增加而
总 token 没有等比例增加的主要原因。

保持不变的是 common / relative 的**分账**：两个块仍然分开，共同需求的结论仍然不得被读成
「谁在赢」（`docs/CHAIN_EVIDENCE.md` 不变式 1）。按层切分只改了作用域，没有改隔离规则。

### D15 — 两类命题的定向：common 答「多少钱」，relative 答「选谁」

这条分工**本来就在代码里**，只是此前没有被写成设计：`chain/factor_evidence.py:115` 一行写死
`if claim.kind != "relative" ... continue`，所以结构因子只吃 relative；common 命题此前只进
行业分析师的「供需」块。新流水线把它显式化并各自归位：

| 命题类型 | 去向 | 回答的问题 | 形态 |
|---|---|---|---|
| `common` | 层级分析师 | 这一层该给多少钱 | 结论 + 覆盖率 + basis（自述/交叉印证） |
| `relative` | 结构分析师 | 层内怎么排序 | 逐家读数 → `moat_pricing` / `tech_tenor` 因子 |
| `relative` | 层级分析师的选股段 | **为什么**选它 | 读数原文（不是因子分数） |

**relative 走两条路不是重复计价**：结构分析师把它压成一个数进复合排名，层级分析师读的是
原文用于写理由。两者一个定量、一个定性，冲突时以读数原文为准（spec 已规定证据优先级）。

**common 不进结构因子，这条不能松**：`docs/CHAIN_EVIDENCE.md` 不变式 2——「竞争者变强 ≠ 我方
变弱」，没有直接的份额/认证/ASP 证据时不得推导我方份额下降。common 结论若能改因子，就等于让
「行业需求好」改写「谁在赢」，正是不变式要挡的东西。

实现上因此要求 7.1 产出**两个分别定向的块**，而不是一个大块广播给所有消费者。

### D16 — 宏观退出 sector 链路，只在 Chief 作用

**现状是同一因素两个落点**：`assemble.py:116` 把宏观注入行业分析师，`chief/assemble.py:54`
又把宏观评审的 `sector_tilts` 注入 Chief。

**改为单点**（2026-08-20 用户裁定）：层级分析师、结构分析师、跨层轮动**都不吃宏观**；
宏观只在 Chief 作用于总仓位与板块倾斜。

**两个理由**：

1. **双重计价。** 宏观在 Chief 已经有落点，层级再吃一遍，同一个利率/风险偏好判断被算两次。
2. **归因污染。** 层级结论变差时分不清是产业景气变差还是宏观变差——而这两者对仓位的含义
   完全不同（前者该减这一层，后者该减总仓位）。

**层级分析师判周期位置用产业证据**：capex 指引、WFE 订单、交期、库存——不是利率观点。
半导体周期确实部分由宏观驱动，但那条传导**已经体现在产业读数里**了，再叠一层宏观判断是
把同一个信号数两遍。

**这是撤销一个现有行为**，所以记下代价：行业链路从此看不到宏观，若 Chief 的宏观块不足以
覆盖某个跨层的宏观影响，系统里将没有别的地方接住它。可接受的理由是 Chief **同时**拿到
宏观评审与行业评审，融合点本来就该在那里——那是唯一一个两种视角都在场的地方。

### D17 — 报告形态：每层一份（含截面），结论先行

**首跑暴露的三个事实**（2026-08-20，看真实产出的文件才发现）：

1. **周度评审根本不写截面报告。** `cross_section.write_report` 只在 CLI 的
   `run_cross_section`（`ats sector crosssection`）里被调用；`_run_layered` 走的是
   `run_layer(persist=False)`，**不写文件**。所以每周跑完只有一份总报告，各层截面文档
   全靠手动补——L7/L8 因此从来没有过。
2. **同一天出现了新旧层键的文件**（`L3_dc_infra` 与 `L3_dc_power` 并存）。那是迁移过程中
   一次跨在配置写盘两侧的任务留下的垃圾，不是新逻辑产生的——但它说明**没有任何机制保证
   一次运行只产出当前层键的文件**。
3. **每层的信息散在两处**：截面文件管排序与权重，总报告的一个章节管配置结论。而
   `layer_cap` 只有在配置结论出来后才确定，所以截面文件里的那个数**单独看是半成品**。

**方案**：一层一份文件，截面并入；`ats sector crosssection` 从此只打印不写文件
（它是调试工具，写文件只会制造第二份不同步的文档）。

**节序：结论先行**（用户 2026-08-20 明确要求）。

```
一、本层结论      层配置 + 预算 + 周期 + 逐票建议权重/stance 表   ← 单独看完就能下单
二、议题证据链    为什么是这个配置
三、截面明细      为什么是这个排序（因子 + relative 逐家读数）
四、逐票取舍理由  为什么选它
五、候选追踪议题  下一轮的输入
```

**为什么不是「证据在前、结论在后」**：后四节是给要核对的人准备的——没有它们，第一节
就只是一个断言；但把它们放在结论前面，等于每周先读三千字才看到答案。两种需求的正确
解法是**顺序**，不是取舍。

### D18 — 证据链与逐家读数：数据早就有了，只是没渲染

第②③节需要的东西**全部已经存在**于 `ClaimAssessment`，此前只喂给了提示词：

| 报告要展示的 | 已有字段 | 此前去了哪 |
|---|---|---|
| 结论 + 依据强度 | `verdict` / `basis` | `_demand_lines` → 提示词 |
| 证人覆盖率、独立证据簇、立场类别数 | `coverage` / `evidence_clusters` / `stance_classes` | 同上 |
| 支持/反驳累计 | `support_score` / `refute_score` | 同上 |
| **未发声的已声明证人** | `silent_witnesses` | 同上 |
| 逐句判读（谁说的·维度·理由） | `judgements[]` | 同上 |
| **relative 逐家读数** | `entity_readings[]` | `_pricing_lines` → 提示词 |

所以这不是新建取数，是**把已经算好的东西同时给读者一份**。`assemble` 里那两个格式化函数
（`_demand_lines` / `_pricing_lines`）的输出形态本就接近报告所需，改造点是让它们的数据源
可以被 `report.py` 复用，而不是各写一遍。

**判读逻辑一行不动**（Non-Goals 已声明）：三道闸、去重、立场加权、极性判定都不碰。

**沉默必须可见**是这一节的硬要求：`expect_from` 存在的全部理由就是让沉默显示成缺口而不是
中性（配置里多处写着这条）。如果报告只渲染「说了什么」而不渲染「谁该说却没说」，
那条纪律在最终产物上就失效了。

### D19 — 候选追踪议题：只进报告，与归纳引擎分工

层级分析师读完本层全部素材后，提出尚未预设但值得追踪的议题。**与既有 induction 引擎
是两条独立的路，写死分工免得以后混**：

| | 触发方式 | 素材 | 出口 |
|---|---|---|---|
| `chain/induction.py` | **确定性**（未映射观测积累到阈值） | 未映射观测 | `claim_proposals` 表 + 人工采纳 |
| 层级分析师 | **语义**（它读到了什么） | 本层全部上下文 | **仅报告** |

**为什么不进 `claim_proposals`**（2026-08-20 用户裁定）：轻。**代价要记下来**——它们
**不去重、不被跟踪**：下周可能再提一遍相似的候选，而你无从知道哪些已经看过且否决了。
`claim_proposals` 有 `signature` 做去重、有 `status` 记采纳/拒绝，正是为这件事建的。
若跑几轮后发现重复提议成了噪音，再把它接进去——**接进去比拆出来容易**。

**两条硬约束**：
- 候选**不参与本期任何计算**：不影响配置结论、不影响截面排序、不影响权重。
- 候选必须说明**谁能作证**与**什么读数会证伪它**。说不出这两样的候选不该提——那正是
  `CHAIN_EVIDENCE.md` 对命题的基本要求，候选阶段就该守住，否则只是换个地方写空话。

## Risks / Trade-offs

- **[搬迁中丢失注释或命题]** → D11 的不变量脚本；搬迁提交与新增功能提交**分开**，
  使 `git diff` 在「纯搬迁」那一提交里应当只显示位置移动。
- **[调用数从 ~9 增至 ~17]** → ✅ **2026-08-20 实测已核对，结论好于估算**：
  八层合计 105,533 字符 + 跨层轮动 6,791 = **112,324**，对比改造前单次全行业上下文
  **128,879** —— 调用数翻倍而输入总量**下降 13%**。原因是 36k 静态合集与 44k 判据笔记
  不再整份发给单次合成，每层只拿自己那几份。单层区间 5.2k（L3 无命题）~21.9k（L5）。
  实跑耗时约 10 分钟。**无需压缩轮动输入。**
- **[层级分析师产生「每层都有话说」的噪音]** → 沿用 `sector-analyst/SKILL.md` 已有的校准
  纪律：多数周是「无变化」就直说；证据不足强制标配 + confidence ≤0.3。反转触发条件必须
  可在下一轮核对，这本身就是对空话的过滤器。
- **[使用率把周期判断变成追涨杀跌]** → 使用率只在 cap 内下调，不放大；且结论必须引用当期
  议题结论，而议题是季度级证据驱动的，不是价格驱动的。
- **[新增标的的数据质量]** → 韩股/分拆新股的 `fetch_light` 字段可能缺失。`rank_cohort` 已有
  `data_ok=False` 路径（排最后、不参与定权），先跑 `sector probe` 确认缺失面再决定去留。
- **[BE 的因子取不到]** → 盈利尚未稳定的公司会同时打中三条路径：`fwd_pe` 可能为空 → `peg()`
  返回 None → value 因子记 0（cohort-neutral）；`rev_growth` 若为负则 `peg()` 也返 None；
  市值若低于 `LIQ_FLOOR_USD`（5e9）还会吃流动性折价。**这些不是 bug，是既有的降级路径**，
  但叠在一起会让 BE 的复合分主要由动量与修正决定。任务 4.3 必须实测这三项，结果写进配置注释；
  若三项全空，BE 只作为叙事与议题证人保留、不参与定权（等价于 `cohort_extra` 的处理）。
- **[电力层零命题，其结论无证据支撑]** → 层级分析师必须**显式标注**「本层无命题」，
  而不是走「证据不足 → 标配」那条路。两者原因不同：一个是**配置缺口**（该建命题没建），
  一个是**证据缺口**（建了命题但这季没人说话）。混在一起，配置缺口会被当成「行业没消息」
  而永远不被发现。spec 已把二者分成两条 scenario。
- **[kb_review 第一轮会对 L6 报警]** → 存储层挂着 `HBM存储.md` 却含 NAND/HDD，命中①盲区标记
  的「该层已有 KB，但未覆盖这些名字所属的环节」分支。**这是它该做的事**，不是误报；
  预期它会要求补写 NAND/HDD 的判据笔记。本次不补（先看两轮读数值不值得补一份笔记）。
- **[候选议题不去重、不被跟踪]** → D19 的已知代价。缓解只有一条：候选必须带证人与证伪
  条件，说不出就不许提——这至少把「重复的空话」压成「重复的具体提议」，后者你一眼能认出
  上周看过。若成为噪音，接进 `claim_proposals` 即可（它有 signature 去重与 status 记采纳）。
- **[层报告体量变大]** → 五节全展开后每层可能数千字。结论先行的节序正是为此：第一节自足，
  后四节按需下钻。若实跑后发现第②节过长，压缩的是**逐句判读的条数**（保留全部维度与
  沉默证人），不是砍掉整节——砍掉整节等于回到「结论是个断言」。
- **[归纳引擎的历史提议带旧层键]** → `claim_proposals.layer_hint` 里的旧提议指向 `L5_fab` 等。
  按 D4 一律走 `legacy_keys` 解析，不改写旧行。
- **[group cap 增加了一条新的 breach 来源]** → ✅ **2026-08-20 用实盘持仓核对通过**
  （net_liq 250,934）：`fab_memory` 合计 27.5%/30%，与拆分前的 `L5_fab` 27.5%/30%
  **完全一致**；`dc_infra` 4.0%/15% 同理。**拆层没有放大敞口，也没有凭空造出违规。**
  唯一的越限是 `L5_chip_design` 19%/15%，而它**拆分前就以 L4_chip_design 19%/15% 存在**。
- **[⚠️ group 护栏一度加在了错的一侧]** → 首跑发现：group cap 只加在 `risk/assess.py`
  （查**已有持仓**），而**分配预算**那条路只认单层 `weight_cap`。L6+L7 同时超配会提议
  25%+20%=45%，越过拆分前的 30% —— **等它响的时候超额仓位已经建出来了**。
  修法是 `cross_section.budgets_for`：组上限只能在**每个成员的诉求都已知**之后施加
  （单层看不见彼此），越限时按比例缩而不是按配置顺序截断。修后实测两组都精确卡在
  15.0% / 30.0%，且组内仍按结论倾斜（L4 超配从 L3 拿到 +1.7%，总量不动）。
