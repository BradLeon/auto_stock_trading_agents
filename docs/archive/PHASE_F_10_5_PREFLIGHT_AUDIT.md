# 10.5 前置考察：Layer / Sector / Macro / Technical（2026-10-16）

> 只读考察，没有改代码、没有调模型、没有写生产数据。对照依据：`docs/ARCHITECTURE.md`（§3 Dataflow、§4 Data 与 Agent 对接、§7 角色契约、§8 调度、§12.1 数据边界）。

## 一句话结论

**四个消费者里只有 Technical 现在就具备切换条件。** Macro 能跑但有一处违反边界（分析中直连网页搜索）且区域数据过期一个月；Layer 和 Sector 的数据底座严重不足：产业链证据从 8 月底起就没再更新，30 只截面标的只有 7 只有受治理的财务数据。另外四个分析师写进 Workflow Memory 的投影都比 ARCHITECTURE §7.3 要求的薄，Sector 只有一句"行业级"立场，没有层次和标的两级配置。建议先补数据流、再决定投影要不要补齐，然后才进入 10.5 的切换步骤。

## 一、它们依赖的 Dataflow 是否已采集所需数据

| 消费者 | TARGET 规定读什么 | 现状 | 判断 |
|---|---|---|---|
| **Technical** | 实时市场包（价格、成交量、VIX，§4 `MARKET_DATA`），不落库 | 运行时价格网关可用：NVDA/TSM/ASML/^VIX/^VIX3M 均取到，最新 K 线 10-15/10-16（来源 yfinance） | **满足** |
| **Macro** | 宏观数据包（经济、财政、利率、流动性、地缘与指数，§4 `MACRO_DATA`） | FRED 运行时指标 21 个可取；**台湾 IC 出口、韩国半导体出口只到 2026-08**（9 月数据 10 月初已发布，月度任务 10-15 错过宽限未补跑）；FactSet 指数材料最后 10-02（周任务错过） | **部分满足** |
| **Layer** | 产业链数据包 + 信息文档包（§4 `HIER_DATA` `DOC_DATA`） | 见下表 | **不满足** |
| **Sector** | 产业链数据包 + Layer 投影 | 同 Layer；另依赖 Layer 先产出 8 份投影（生产里一份都没有） | **不满足** |

| L5 芯片设计 | 4 | 3/4 | 4–36 | 2026-08-30 |

- **财务：** 30 只截面标的只有 7 只有受治理财务数据。读模式已是 `platform`（不回退到供应商），所以其余 23 只在截面里会显式缺失，不会被悄悄补上。
- **证据事实：** 全部 6,573 条中性证据都是 **2026-08** 观测的，9、10 月为零。原因：证据抽取挂在旧调度器的 PEAD 打分窗口里（`_observe_window`），而 `config/settings.yaml` 里 `pead_observe_window: false`（你设的，注释写明"仅影响排程内的自动抽取；手动 evidence observe 仍然可用"），旧调度器本身也没加载。按 ARCHITECTURE §3，数据采集应由数据平台的刷新控制器隐式完成，不该依附在某个分析工作流的时间窗上。
- **L1 观察者数据：** OpenRouter 排名 10-15、前沿 AI 能力 10-16 是新的；Ramp 停在 09-11（每 10 天任务错过）、BTOS/RPS 09-10、Anthropic 指数 09-06。
- **L6 DRAM 合约价：** 最新期 2026-08-16。
- **共识：** 平台里有 30 只标的的共识，但每日刷新只覆盖 11 只 PEAD 目标；其余快照停在 9 月。Sector 读共识（`sector_consensus`）没有接上今天加的期次/新鲜度核对，会照用过期值。

## 二、四个 Analyst 的 Workflow 是否符合需求

**符合的部分**
- **分析师隔离（§1-1、§7.2）：** 四个模块里没有读取其他分析师观点的代码（只读各自上一期结果做滞后判断）；架构守卫测试 45 项通过。
- **依赖（§8.2）：** Sector 只等 Layer，Dispatcher 计划会自动带上 Layer，且 Sector 要求恰好 8 份有效的 LayerAnalysis；Macro、Technical 无分析师依赖。
- **调度条目：** `research_schedules.yaml` 已有 Technical（工作日）、Macro、Sector（周六）条目，均未启用。

**不符合或需要你知道的部分**

| 角色 | ARCHITECTURE §7.3 要求的产出 | 实际投影内容 | 缺口 |
|---|---|---|---|
| Layer | 层级、实体关系、**标的横截面排名、共同与差异证据** | 层状态、摘要、要点列表、置信度 | 截面排名和证据引用没有结构化，只在文字里 |
| Sector | **行业 / 层次 / 标的三级配置及事实引用** | 只有行业级：立场、目标权重、理由、驱动因素 | **层次和标的两级配置不在投影里**（在旧报告里），Chief 只能读到一句行业立场 |
| Macro | regime、**影响传导、情景、时间范围、主要风险** | regime（4 档）、摘要、指标列表 | 传导、情景、时间范围、风险没有结构化 |
| Technical | 量价读数、趋势状态、**失效条件、建议敞口** | 信号、摘要、价位 | 失效条件和建议敞口没有结构化字段 |

- 投影 schema 是 `extra="forbid"`，补字段等于升 schema 版本，Chief 读取侧也要跟着改。
- **运行节奏：** 旧调度里这几项是你关掉的：`technical_daily: false`、`weekly_review: false`、`macro_sector_event_triggers: false`。旧路径最后产出：Sector 9-04、Macro 9-12、Technical 9-02。切到 Dispatcher 并启用条目，等于重新开启它们，需要你明确同意。
- **模型：** Layer/Sector/Macro 的角色今天刚从 Terra 换成 DeepSeek V4 Pro，还没在生产里出过结果；`sector_analyst`/`macro_strategist` 的 `max_tokens` 24000 在 DeepSeek 上没验证过。

## 三、Data 与 Agent 的对接是否符合预期

| 检查项（§4、§12.1） | 现状 | 判断 |
|---|---|---|
| 经 Data Products 读取，不直连 Provider | Layer/Sector/Technical 经 `data/products` 下的入口读取 | 基本符合 |
| **Macro 分析中直连外部搜索** | `macro_inputs.search_news` → `websearch.search_news` → **Tavily 网页搜索**，`TAVILY_API_KEY` 已配置，每次宏观评审都会实时调用 | **违反 §12.1-3「Agent 不得直接调用 Provider」**；按 §4，宏观的政策与地缘材料应来自准入后的文档 |
| Macro 宏观指标的数据形态 | FRED/yfinance 运行时拉取，代码注释写明"刻意不进持久层" | 与 §3 把"宏观指标"列为持久化结构化来源**不一致**，是有意偏离，需要在 TARGET 里登记或改掉 |
| 声明的读取接口 | 覆盖登记写的是 `ats.data.consumer_api.read_input`；实际这四个都走各自的产品入口，只有价格读取会记录读取血缘 | Information/Fundamental 那种逐次读取留痕，这四个**大多没有** |
| 人工策展知识 | 直接读 Obsidian 文件 | §3 把知识库列为共享事实层，读法可接受，但没有版本和血缘 |
| Technical 价格来源 | 实际用 yfinance | 覆盖登记写"券商故障时仅目标标的回退"，与实际不一致，待核实 |

## 四、对 10.5 的影响与需要你决定的事

**结论：** 现在照之前的 10.5 计划直接切 Layer/Sector，切过去也只能在 8 月的证据、23 只缺财务的截面上跑，产出价值有限；Macro 也会带着一个边界违规上线。建议先处理数据流，再切换。

需要你决定：
1. **证据抽取放在哪：** 按 TARGET 把证据抽取改成数据平台刷新控制器的定时任务（推荐），还是重新打开旧调度器的 `pead_observe_window`，或者暂时接受 8 月的证据。
2. **财务覆盖：** 是否为 23 只缺财务的截面标的补齐受治理财务包（美股可走 SEC companyfacts，ADR/海外标的需另定来源），还是接受截面显式缺失。
3. **Macro 新闻：** 把 Tavily 实时搜索改为读取已准入文档（推荐，符合 §12.1），还是在 TARGET 里登记为例外。Macro 指标的运行时形态同理：登记偏离，还是迁入持久层。
4. **投影补齐 §7.3：** Sector 三级配置、Technical 失效条件与建议敞口、Macro 情景与风险、Layer 截面排名与证据引用，是放进 Phase F 做（要升 schema 版本、改 Chief 读取），还是记为 Phase F 后的事项。
5. **重新开启节奏：** 这几项在旧调度里是你关掉的。切到 Dispatcher 后是否让它们按条目运行（Technical 工作日、Macro/Sector 每周六）。

**可以先做、不受上面决定影响的：** Technical 的健康检查、数据版本、读路由切换、首跑与调度演练。它不调模型、数据满足、对接也符合。
