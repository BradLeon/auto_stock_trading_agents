## Context

参见 proposal.md。此为 `complete-target-dataflow` 的关联子专项，交付父任务 2.2.9、2.2.11、3.1/3.2 所需的 FactSet 局部证据，不继承其他来源问题，也不替父 change 签发全局资格。方案涉及解析、准入、产品与历史兼容，需要独立设计。

现有 `FactSetWeeklyPipeline` 已调用旧 PDF、文本与图表模块；无需因目录名称重写下载和存储。数据库已有 2026-08-28 sector_core platform release、231 cells；2026-09-18 PDF 为 33 页，Index 发布 15 项，Sector 为 0 cells / shadow。对后者真实原始文件重放，082826 解码器返回两张局部表和大量 unreadable_cell/raster_missing；编排在整体解码失败时把表全部置空。自动入口未传 annotated_cells_ok，产品又只选择与最新 Index 相同版本的 Sector，导致历史已发布行业数据被表现为 registered_no_data。

## Goals / Non-Goals

**Goals:** 同一解析代码、配置版本与模型策略（如有）处理两份真实 PDF；全程保留原文、标签、期间和证据，恢复可靠的周期采集及 Macro/Sector 数据产品。治理规则集中管理，已有成熟能力复用。

**Non-Goals:** 不保证任意 PDF 无人工干预；不下载第三方转载替代官方材料；不重写 Agent 决策，不改变跨分析师观点依赖，不切交易流；不把全部公司 Top/Bottom 榜单扩展为公司财务数据库。不用外部付费视觉服务作为默认依赖。

本次不再以全行业全部单元格自动解析成功为交付目标。用户最新确认的优先级取代此前全行业等权验收要求；准确性、证据、隐私、幂等和历史可见性要求不变。

## Decisions

### 0. 投资相关性优先，覆盖与准确性分开管理

| 层级 | 范围 | 投入和验收 |
|---|---|---|
| 核心 P0 | S&P 500已登记总体盈利、营收、预期、估值及有界宏观叙事；Information Technology（GICS_45）的八类指标及所有披露目标期间 | 必须完成双报告独立核验、生产入口与消费者读回；核心缺口不能以低优先级豁免 |
| 相关 P1 | 原文明示的AI硬件、半导体、消费电子及上下游信息 | 优先保留有来源的叙事/事实，不新增穷尽公司和子行业结构化指标的硬门槛 |
| 补充 P2 | 其他行业详细指标 | 复用通用解析，已可靠获取的值照常保留；疑难项留痕，不阻塞核心交付 |

Technology、Info. Technology等标签只有在本报告上下文能确认同一行业时才归一到GICS_45。科技行业汇总不等于AI硬件或消费电子子行业；不能从汇总数值推算子行业，也不能把整个Consumer Discretionary行业当作消费电子。跨行业的相关信息按原文明示实体和主题保留，不修改行业归属。

每份报告先建立版本化范围清单（层级、实体、指标、期间、适用性和证据），独立于解析结果冻结核心范围。核心Index沿用已登记且本期适用的指标，不靠挑选成功字段缩小分母。P0先完成端到端，再扩展P1和低成本P2；P2通用解析失败后停止专项调参与逐格补救，记录失败/延期原因及已耗资源，不追加专门模型批次。共有解析器的修复可同时惠及所有行业。原有模型总预算继续有效，不因优先级修改自动增加授权费用上限或无限重试。

P1/P2延期不等于not_disclosed或成功。独立记录处理状态与优先级；原文、已有标注、候选及历史发布均保留。宏观总量使用报告原生S&P 500数据，不能用科技行业或不完整行业样本代替全市场总体。

### 1. 按业务职责复用，不按文件夹重新实现

保留 fetch_report、inspect_pdf、文本提取、文档版本和 observation/evidence/release 存储。新通用图表解析在现有 FactSet sources 模块演进，跨领域编排留在 pipelines/factset_earnings_insight.py。旧日期专用解码器仅保留历史回放，不进入新生产策略或双报告验收路径。替代方案“把所有代码搬入 unstructured 并重写”增加回归而不解决定位问题。

### 2. 语义定位和逐期标签识别

流程为 PDF 页面/图像清单 → 章节/标题/表头发现 → 图表候选与期间识别 → 动态行列/标签定位 → 数值候选 → 证据与关系校验。原生文本优先；图像使用本地 OCR 的词框和空间关系识别标签、图例、列及数字，不预设行业排序。根据标题和局部锚点确定裁剪范围；页码、图片编号和 bbox 是输出证据，不是报告日期索引的输入常量。

识别失败保存原图与阶段原因。禁止固定行业位置、硬编码量程/像素颜色估算精确数值、自动补负号/小数点来凑答案。视觉模型不是首期必需依赖；若后续需外部服务，先确认授权、成本与数据传输。任何 OCR/模型候选均不能凭自身置信度发布。

2026-09-27用户授权增加OpenRouter视觉辅助解析，以上外发前提已满足。首个适配器使用已核实支持image输入的`openai/gpt-5.6-terra`，模型和prompt版本、请求/图片/token/超时预算登记于既有structured.yaml。只发送必要原图裁剪及不含预期值的转录指令，不发送完整PDF、账户信息、OCR答案或golden；固定OpenRouter HTTPS端点、禁止重定向，请求`data_collection=deny`和ZDR，不静默降级隐私策略或更换模型。读取.env中的专用key，兼容已明确指向OpenRouter的OPENAI配置，不记录密钥。

每次返回保留模型、usage/cost、prompt/策略hash、原图/crop hash、bbox和原始响应。失败消耗预算、没有无限重试；重复/缺失ID、非预期字段或截断响应失败关闭。OCR与视觉不一致时记录冲突，不用视觉值静默覆盖；一致也仍须通过原文独立核验和组完整性。该通道不读取golden；离线验收在模型调用完成之后单独比较。

### 3. 统一策略注册，维持事实精度

八类指标及全期间语义保留，但强制完整性限于预先登记的核心实体范围，而非所有11行业。旧golden中的revenue_growth/revenue_surprise not_applicable已被原文否定，不能继承错误豁免。发布组身份至少包含指标组、目标期间、期间基础、估计状态和实体范围，不能仅以chart_id聚合不同季度或混用核心范围与全行业范围审批。CY与FY不可互换；历史比较列作为comparison证据保留，不冒充另一当前报告期观测。

unstructured.yaml 管理 PDF 来源、权限、获取预算和文档准入；structured.yaml 管理派生指标组、标题别名、单位、期间规则、必需列、合计容差、发布条件与审阅策略。沿用两表装配入口；不新建第三份 source registry。解析算法仍是代码，业务质量规则及策略版本可审阅、可追溯。

优先级、核心实体/指标范围、范围版本和补充层停止规则亦归入既有structured.yaml策略，不引入第三个注册入口。范围变化进入策略/候选hash，使旧审批不能跨范围复用；先前2.1已完成的是原契约，新增范围契约需独立实施验收。

候选保留 report/document version、GICS entity、metric、value、unit、target period、estimated/actual、原始行业标签与数字 token、页码/bbox、提取器和策略版本。报告日期不替代目标季度；同一指标的不同估计状态不能混合比较。

用户已确认二态规则：只有原文明示该指标、该期间为实际业绩才使用actual，其他情况（包括blended、预测、未说明状态）统一estimated。无需增加第三种估计状态，也不因缺少状态说明阻塞发布。actual证据须关联本组并纳入候选hash及独立审阅，不能将别处的actual、条件句或少量公司已发布业绩推及全行业；原始措辞完整保留。二态是本系统的简化分类，不改变指标本身语义（例如P/E仍为倍数）。新策略版本使旧审批不能复用；旧记录按原状态读取，不能原地修改历史hash。提取失败、待审、冲突等处理状态与估计状态分离，数值、实体、单位和期间错误仍然阻塞。

八类覆盖：scorecard、surprise、growth、margin、guidance、geographic exposure、valuation、ratings/targets。先完成Index与科技行业增长的端到端链路，再完成科技行业其他指标，不先穷尽其他行业。每期适用性由独立材料清单确认，不从解析失败反推出“不适用”。仅声明完整11行业横截面时要求11行；核心科技发布要求该实体的适用列/期间完整，不因其他行业缺格被连带阻断。

比较日图例如30-Jun没有年份时，按注册表的`latest_occurrence_on_or_before_report`规则规范为报告日当天或之前最近一次该月日（限366天内），保留原始图例并由策略hash追溯推导规则。这是比较快照日期的规范化，不是用报告年份替代图表目标期间；完整日期不得重解释，非法日期保持失败。该规则同样适用于跨年报告，不按8月或9月编写分支。

### 4. 分组验证和有依据的发布

区分 not_disclosed（有证据）、not_located、extraction_failed、conflict、pending_review、validated、published；报告季阶段用于解释适用性，不是无条件豁免。可解析的局部候选全部保存，一组失败不清空其他组。

按声明的实体范围验证标签、适用列、期间/单位和关系约束。核心科技范围可独立发布；全行业范围仍须11行业完整。任何范围都不降低单值精度、原文证据或行内合计要求，单一OCR置信度不能批准。若共享表头、期间或单位存在歧义，所有依赖该证据的实体均被阻断，不能借实体拆分绕过质量错误。

分别提供`core_acceptance`（passed/blocked）和`report_coverage`（complete/partial）及各层级、实体、指标、期间缺口。核心通过且只有P1/P2缺口时允许本change按核心范围验收，报告覆盖仍为partial；Index通过但科技核心失败时core_acceptance必须blocked。sector_core兼容摘要保留partial，旧消费者不得把核心范围passed当全行业完整。历史已发布值继续可查，不能删除补充行业来伪造complete。

准入以登记的质量与完整性规则自动判定：Index 与科技核心组在证据、数值、期间、关系和范围检查均通过时，持久化绑定本次 PDF、候选和策略 hash 的策略审批记录并发布；异常留在 shadow/待审，只在此时请求人工判断。人工审阅记录绑定 PDF hash、候选集合hash、提取器/策略版本、指标组、实体范围及范围版本、审阅结论、操作者身份与时间，并保存证据引用；新报告、候选或策略/范围变化使旧审批失效。不能将 annotated_cells_ok=true 或测试审批当有效生产批准。Golden 是独立验收资产，生产解析器不能读取；由原文核实的人工修正若作为正式数据，必须标明 manual_reviewed，不能冒充解析器自动正确。

### 5. 产品兼容与历史可用性

默认当前报告视图保持同报告口径，按组返回状态/覆盖率/缺失原因。另提供显式 latest_valid_history，逐组带报告日期、document version、known_at 与本次失败，不把8月值拼成9月完整截面。最新已发布月报的可用性不按距今天数降级或发 stale 年龄警告；若有更新报告未发布，另以 `newer_unpublished` 标识，采集失败保留在独立运维状态。原有 index_core/sector_core 接口提供兼容摘要，不能让旧消费者忽略 partial 标签。历史 manifest/vintage 不删除、不改写、不伪造 known_at；新增分组发布维度优先复用现有 release manifest，必要字段采用兼容增量。

### 6. 同逻辑双报告和独立验证

建立本地受管 fixture manifest：至少 2026-08-28 和 2026-09-18，记录官方 URL、报告日期、hash、首次采集时间和存储位置。8月复用已有原件；9月在实施时经受管队列重新获取官方日期版核实，已保存的9月原件可先用于离线回放。稳定 URL 若已指向其他期，不替换固定双报告样本。网络不可达时记录外部阻塞，不影响已有原件离线验证，不伪称本轮下载成功。

先逐份审阅原文建立分层图表/列/实体/期间清单，再冻结核心golden。两份样本使用同一解析入口、范围策略与策略hash，运行隔离，禁止日期/hash分支及读取golden。已有231格历史资产及770格独立转录保留供低成本回归，但不要求全部格成功才能交付。核心适用且可读目标必须逐格对齐，原文未披露须有证据；未决核心缺口阻断验收。补充项仅允许明确延期，任何拟发布值仍须同等核验，错误值不得发布。验收报告同时列出核心结果、全报告覆盖和延期项，不靠缩小分母伪造全量通过。

额外测试页序、图像编号、行业排序、分辨率、缺列、负值、小数点和跨季度语义；扰动测试不得将数字位置改变却不改变标签。两期通过只证明这两期与约定扰动集，不宣称无限泛化；以另一未参与调参的真实报告做上线后的持续回归。

## Risks / Trade-offs

- [两份报告被过拟合] → 禁止日期定制；同策略hash、标签重排负例和后续未见报告回归。
- [数字看似合理但归属错误] → 标签与数字联合定位、独立原图审阅，不仅做范围/求和校验。
- [本地OCR不足] → 保留待审与原文，不凭置信度自动发布；实测后再讨论额外模型授权。
- [分组发布使消费者误混期间] → 同报告默认视图、显式历史视图，完整性与as-of契约测试。
- [质量规则集中后增加维护量] → 统一指标语义与配置校验，不将具体页面坐标变成另一种硬编码YAML。
- [审阅成本] → 双报告严格建立核心基线；已有全行业标注保留复用，P2不逐格反复补救，重复hash/候选幂等复用。
- [核心范围被误当全行业或AI子行业] → 范围身份和双状态显式输出；子行业结论只能来自明示原文，不能从GICS_45总量推导。

## Migration Plan

1. 保存原始双报告与历史发布基线，冻结分层范围及核心golden，梳理旧能力复用点。
2. 先贯通Index与科技行业增长，再完成科技行业其余组的提取、范围准入、审阅与消费者读回；隔离回放，不改变现行读路由。
3. 完成同逻辑双报告核心验收、故障、幂等、修订和as-of验证；明确P1/P2延期，保留所有缺口及原始材料，不等待补充行业逐格攻关。
4. 用唯一受管任务执行真实获取/重处理，验证 Index/Sector/文档读回、按纽约时间月末调度去重及失败恢复。目标报告月份与源文档日期须一致；Mac 休眠后的补跑及官方 URL 已指向次月的情况分别留痕。不得把手动试跑当作自然调度证据；受控回调和自然月末运行各自记录。
5. 通过后按来源/消费者分离开关渐进启用新解析及产品；回滚只撤销新发布选择/恢复稳定产品，保留所有版本。将证据交回父change，不自动勾选其复合任务。
