- 两来源均未在标题中出现当前八个采集股票的大写 ticker；按现有别名规则，标题命中对应公司名／别名的数量分别为 1 和 19。此统计不包含所有公司，不证明其余标题没有公司，也不能把规则漏识别当成作者习惯。
- SemiAnalysis 混合使用公司名、产品名、技术主题和观点型标题，副标题常补充文章范围。TrendForce 混合公司事件、产品／工艺新闻及行业价格综述；来源不同不意味着情景互斥。

采集／关联规则的离线覆盖集合来自实际配置；当前 IBKR 集合为 NVDA、AMD、AVGO、MRVL、TSM、MU、ORCL、MSFT。四标的真实业务审阅集合仍为 MRVL、MSFT、NVDA、TSM，分别给出候选和缺口。配置中的其他标的也须记录采集结果，但不因此扩大本轮真实模型范围。公司／产业链关联允许集合按当前授权 scope 解析，不能仅限于八个查询合约。

## 3. 开发方案

### 3.0 先修复候选字段与可见文本

由数据平台利用本次已取得的正文／HTML／邮件头解析，而不是让 Information 直接取网页或邮箱：

- TrendForce 优先保存已取得页面的原始标题；尚未取得时保留 slug 还原标题并标记来源／质量。不能从 `783`、`107 4` 等 slug 片段猜回百分比或金额，也不能为每个候选无预算地再取页面。
- SemiAnalysis 分别保存正式标题、副标题／导语和 publisher。元数据缺失时，可从现有邮件头、HTML 标题或明确正文标题补充，并保存定位和恢复来源；不能凭主题生成标题。
- 发布时间仅从可核验的邮件头／页面／来源记录恢复；年、时区或日期仍不确定时保留缺口。不得以 fetched_at、本文日期或作者位置猜测发布时间，缺时间的材料不能按“新消息”通过窗口检查。
- 清理邮件 padding、导航、重复标题及订阅按钮形成用于分析的文本视图，保留原始不可变正文；记录清洗版本、有效字符数及与原文的定位关系。正文中引用的他人观点、订阅提示本身不能粗暴删掉。
- 该产品当前没有独立摘要，候选初筛优先使用可见副标题／导语；如复用已有摘要，保留生成来源和版本，不把人工审阅概览冒充已保存的模型摘要。

已存文档的标题、时间、关联与完整性修订都走元数据发布规则。对有冲突或无法恢复的字段如实拒绝相关用途；修订后的 known_at 不回填旧时点。不能只修新增材料而让存量 no_change 路径继续携带错误标签。

### 3.1 预算及选择顺序

保持“发现标题 → 候选处理 → 取正文 → 准入”的数据平台流程：

- 先复用原生 ID、规范 URL、同标题同精确时间等确定性去重，再占用正文请求。相似标题不自动证明重复，同一事件的新版本不能误删。
- 初筛使用质量已标记的标题、副标题／导语和现有摘要；缺字段、产品标题、slug 还原标题都不能直接判定“不相关”。仅凭标题未命中，不得断言正文不满足准入；有限探索预算允许取得正文，再按明确证据验证关联。
- 为配置中具有合格候选的标的保留基本请求机会；剩余额度共享。多标的材料只请求一次正文。记录分配方法和排序理由，避免统一最新排序垄断预算；预算小于候选数量时允许延期，但不能静默漏掉一个标的。
- 重复刷新优先复用已存在且完整性适用的正文，给未处理候选续取机会；保留来源版本更新检查，不能永久停止检查已缓存文章。
- 用户已取消每轮24～32次正文请求比较，维持10次上游正文预算。采用请求上限和总耗时上限双约束；失败重试计入预算。

记录发现数、初筛数、缓存命中数、实际请求／重试数、准入数、延期数及各标的覆盖。预算只控制数据获取，不授予模型、交易或其他 source 权限。

### 3.2 实体关联与来源归属

保留出版者身份，补充 related_entities，不把出版者直接替换成目标公司。

- 标题及副标题／导语：复用公司注册名／别名，分别记录命中位置与强度；股票代码识别不得统一忽略大小写，把人名或普通词当 ticker。短 ticker 需要股票标记或明确金融上下文，单独的歧义词不建立正式关联；保留真正 ticker 出现的正例。
- 正文：对清洗后的可见文本做确定性实体识别，映射回原文证据位置。导航／作者栏命中、模糊简称或一次提及不能自动产生高重要性结论；不删除正文中真实讨论公司的人名／公司名上下文。
- 产品／技术主题：用现有配置中的明确关系或 Information 的证据解释确定候选影响；不为 Vera Rubin、TPU、HBM 等无公司标题强行新增动态 mapping。仅产品名或行业关键词不能写回“已确认关联公司”。
- 无明确目标公司关联的行业主题：不进入 Information 阅读候选；两个来源采用相同规则。具名竞争观点等明确目标关联可保留，观点只进 Workflow Memory。
- 查询合约仅为查询血缘，不能作为公司关联证明。若拟将 IBKR 既有 title_verified 策略扩展为正文验证，必须显式记录允许的证据种类、规则版本及拒绝条件；不能仅关闭 require_entity_verified。
- Data Platform 的关联索引用于可发现性；Information 的相关性／影响解释用于分析。来源观点或本角色的关联解释可以作为可追溯上下文；须区分来自原文的观点与模型解释，不把关联当作已证实的投资影响，也不读取其他分析师的私有叙事来改写来源。
- 已存在同正文文档仍需可重建关联。不得因正文 no_change 跳过元数据修复；新增关联发布保留 known_at，旧 as_of 读取仍看到旧索引。文档正文版本与关联版本分别表达，不为关联更新伪造新正文。

使用现有注册公司名／别名确认当前目标；Information 不再以静态 signal_chain 扩大阅读集合，不维护动态 mapping。

### 3.3 来源分级筛选与 Information 接入

| 来源 | 候选策略 | 正文及标的关联 |
|---|---|---|
| SemiAnalysis IMAP/RSS | 利用已登记发件人／publisher 路由，综合正式标题、信息密集副标题／导语；采集发现可含技术主题，Information阅读需明确目标关联 | 按目标scope处理未抽取版本；partial只用可见正文，允许无相关insight |
| TrendForce 网页 | 综合原始标题或已标记的 slug、导语及 News/Insights 类别；公司事件与行业综述分别初筛 | 对公开可读正文建立有定位的关联；行业综述仅在正文等明确关联当前目标时进入阅读，不保证每篇重要 |
| IBKR | 合约查询血缘、公司／别名与有质量标记的标题／摘要组合 | 主预算优先直接候选，探索额度覆盖标题遗漏；正文按明示准入规则验证 |

来源声誉只影响候选路由，不能代替事实可信度。TrendForce 当前是网页源，不假设存在其订阅邮箱接入或受许可研究库访问。

两个来源都执行同一情景矩阵：标题有公司 → 仅副标题／导语有公司 → 仅正文有公司 → 只有产品／行业主题 → 不相关 → 元数据缺失。来源特征决定解析与预算，不预先给“有 ticker／无 ticker”的固定属性，也不把 News 自动判高价值、Insights 自动判低价值。

处理顺序：来源／版本与字段质量检查 → 标题／副标题／导语初筛 → 有限可见正文抽取 → 标的相关性与材料性 → 简报。复用键需覆盖正文版本、清洗／解析、完整性政策及抽取配置；同正文但解释元数据被修订时不能盲目复用旧 full 抽取结果。

接入 `agents/information/extract.py`、`triage.py`、`assemble.py` 和 `entry.py`，先核对当前角色及读取契约：

- 不能通过取消 bound-task scope 来恢复全库读取。抽取要在授权范围内运行，或复用已有独立抽取入口及其合法 scope；不新建额外 Agent/workflow。
- Information不设出版者限定探索通道。publisher材料必须已索引明确目标关联，才能通过该目标DOC_DATA scope发现；消费者不能直接扫库、邮箱或provider。
- 旧 triage 的 thesis 参数不能直接接入 Fundamental 观点；使用中性业务背景或调整该角色内的接口。
- 现有抽取投影按文档组织，而标的简报按标的组织；明确合法消费、缓存复用、去重及血缘，不能假设运行抽取就会自动补齐目标简报。
- 初轮8篇仅为历史测量起点，现已取消篇数截断。保留单篇40,000字符、单目标320,000字符和180秒停止启动调用预算；实际实验总请求、token、费用与期限预先登记。
- 新输入范围不得只查最近两天而遗漏未处理材料：按来源发布时间、未处理版本与原 as_of 选择，记录回补和背景；不把旧材料重新标成新发布。

### 3.4 全文、预览与标题

| 状态 | 消费政策 |
|---|---|
| 全文 | 正常抽取；保留来源性质和时间，不把作者预测当 actuals |
| 实质预览 partial | 仅从可见片段抽取，明确全文未取得及截断原因；不得推断隐藏内容 |
| 仅标题／订阅提示 teaser | 保留为待取得证据的候选，不作为已证实事实输入 |
| 正文解析失败／访问失败 | 记录 acquisition gap，与订阅限制、无相关新闻分列 |

现有 SemiAnalysis 的 2,000 字符分类／准入规则应统一评估。不能仅因短而拒绝有实质内容的预览，也不能仅因长而认为完整。若允许短预览，须增加显式内容类型和有效正文检查；不能笼统降低所有 source 的 minimum_body_chars。

核验存量与新版本的 completeness 和截断证据。正文出现解锁提示时，检查它是否为本文付费边界，还是引用／导航／推荐其他文章；现有分类复算只是定位异常的起点，不能机械把所有提示都判成同一种权限状态。stored=full 与可见边界冲突且未解决时，不以全文消费；按已验证可见范围进入 partial，或保留完整性未知并拒绝全文用途。失败不靠延长正文或修改日期修补。

原始字符数、清洗后字符数及可见实质内容分别报告。先去除 padding 等非内容噪声再判断有效预览，短但有明确事实的正文与长营销段落分别测试。

第一批保留 TrendForce “公开正文”政策；不新增付费研究产品接入。需要预览支持时另行登记该 source 的可见内容准入和消费策略，不能套用 SemiAnalysis 的许可。

模型上下文逐文档传递 completeness、可见长度、输入截断、版本及定位；报告同步呈现。文档全文可读但模型只接收截断正文时，应同时标记两种状态。无权限不能通过生成、拼接营销段落或补写正文来冒充取得全文。

以后获取更完整内容，应保存完整版本及新的 known_at，保留预览版本和既有引用。更完整不自动代表更新发布事件，旧报告不改写。
