# Phase F：部署许可与运行时间裁决

2026-10-10。最终裁决：**上线时批准一次，之后长期运行，直到主动停用**。已同步 Decision 34 与任务 5.16；本次设计裁决不执行生产切换、签核或券商写操作。

## 为什么需要裁决

当前路由 key 含 time_range.start/end，默认 Workflow 每 tick 生成不同点身份；显式较长窗口又要求 end 等于 as_of。因此单次隔离运行成功不能证明连续调度可用。原 Technical 诊断保存在本机 docs/validation/phase_f_read_executor_20261009/scope_window_diagnostic_20261010.json，不重新认证该历史报告。

最初推荐将有限授权窗口与独立运行时点分开。用户进一步明确，不希望上线后日常续批，因此“窗口到期需要续期授权”的解释已被替代；不能用一个很远的到期日期模拟长期许可。

## 最终语义

| 对象 | 生命周期和检查 |
|---|---|
| 持久部署许可 | 上线明确批准一次，在固定业务范围内持续有效；主动停用/撤销后不可继续运行 |
| 单次部署动作凭据 | 如有期限，仅限制该次动作，不能自动决定已明确批准的持续运行许可寿命 |
| 每次运行 | 独立 as_of、查询窗口、Event/version、真实 source/query 时间、run/hash/generation |
| 资格与验收报告 | 当次有效性、TTL、撤销和实现/范围适用性自动重查；失效阻断受影响范围 |
| 实际输入 | 每次检查新鲜度、来源时间、缺项与输入截止，不把部署批准当作数据证明 |
| 单笔交易 | 风控、人工审批和券商写权限继续独立执行 |

部署 scope 固定 workflow、消费者/契约/用途/实体/边界与明确 Event 规则；运行时显式关联当次 qualification/input/report scope。数据查询窗口推进、跨日和已批准规则内的事件版本更新无需再次人工部署批准。未绑定、歧义、范围扩张与规则外事件拒绝；增加范围需要新批准。只批准特定 Event/version 的历史授权不得自动变成事件规则授权。

资格/输入暂时失效不撤销部署许可；证据刷新不能自动解除持久停止。每次运行仍核对停止/撤销和 worker 代次，旧 worker 不能通过换绑恢复权限。历史有限授权保留原期限，不升级既有记录；逻辑 trigger 去重不随授权变化重置。
