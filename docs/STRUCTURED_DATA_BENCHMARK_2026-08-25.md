# 结构化 SQLite 首期性能基线（2026-08-25）

## 结论

首期 SQLite repository 在 12,000 条低频研究观测的合成负载下通过全部预设阈值，不需要提前引入 PostgreSQL、湖仓或外部时序服务。本结论只适用于当前明确限定的财务、Consensus、区域、行业和证据型低频数据；ticker 行情和期权仍为 runtime/excluded，不在本基准范围内。

## 可复现命令

```bash
PYTHONPATH=src .venv/bin/python scripts/benchmark_structured.py \
  --records 12000 \
  --point-queries 200
```

脚本使用临时目录，不读取或修改生产数据库。它执行单线程批量写入、200 次实体指标查询、8 线程并发读取和 4 线程竞争写入。SQLite 没有提供可移植的逐语句“锁等待时间”计数器，因此以竞争写入端到端延迟和 `database is locked` 错误数作为首期锁等待代理；这项限制必须在后续报告中继续注明，不能把代理指标描述成引擎内部等待时间。

|---|---:|---:|---|
| 初始写入量 | 12,000 rows | — | 信息项 |
| 竞争写入后总观测 | 12,120 rows | — | 信息项 |
| 初始写入耗时 | 1.364482 s | ≤ 30 s | 通过 |

| 4 线程竞争写平均延迟 | 0.277160 ms | — | 锁等待代理 |
| 4 线程竞争写 P95 | 0.257000 ms | ≤ 500 ms | 通过 |
| 竞争写错误 | 0 | 0 | 通过 |
| 8 线程并发读错误 | 0 | 0 | 通过 |
| SQLite 文件大小 | 7,401,472 bytes | ≤ 67,108,864 bytes | 通过 |
| 合成 artifact 大小 | 46 bytes | — | 信息项 |

竞争写平均值高于 P95 是因为少量 WAL/连接初始化长尾拉高均值；验收以预先声明的 P95 和错误数为准。该脚本的 artifact 只记录合成批次描述，不模拟真实 XBRL/JSON 文件体积；真实 artifact 容量由后续运维质量报告单独验收。

## 适用边界与后续触发条件

- 本结果证明当前 repository 足以继续阶段二开发，不证明 SQLite 适合高频行情。
- 数据规模、并发和硬件变化后应使用同一脚本重跑并保存新报告。
- 若点查询 P95、竞争写 P95、锁错误或数据库容量任一超过阈值，应先检查索引、事务批次、WAL checkpoint 和查询范围。
- 只有可复现优化仍不达标时，才提出物理拆库或外部服务的独立 OpenSpec 变更。
