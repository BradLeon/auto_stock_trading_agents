## 一、先统一术语：GPU、XPU、ASIC 不是三个互斥集合

市场常把三者并列，但技术上它们描述的是不同维度：

| 术语 | 描述的维度 | 本文中的含义 |
|---|---|---|
| **GPU** | 架构与编程模型 | 面向广泛并行计算、可编程性强的外售加速平台 |
| **XPU** | 功能性统称 | GPU、TPU、NPU、训练/推理加速器等非 CPU 计算单元的总称 |
| **ASIC** | 定制程度 | 为一类工作负载、客户或系统目标专门设计的芯片 |

因此，**XPU 是伞形概念，ASIC 是定制程度，GPU 是一种具体架构与平台路线**。很多云厂 XPU
本身就是 ASIC；现代 GPU 也包含越来越多专用单元。真实竞争不是“通用”与“完全固定功能”
二选一，而是一条连续谱：

> **可编程性更强、适用面更广 ←→ 工作负载更稳定、单位效率更高**

投资分析首先要问的不是“它是不是 ASIC”，而是：

1. 它对哪些算子、精度、模型结构和部署方式可编程；
2. 这种灵活性付出了多少芯片面积、功耗和软件复杂度；
3. 客户是否有足够大、足够稳定的负载，值得牺牲灵活性换取效率。

## 二、价值链角色：设计所有权、产品收入和经济利益要分开

一颗定制芯片往往由多方共同完成：客户定义工作负载和系统目标，芯片架构团队确定方案，
设计合作方完成部分 IP 集成、物理实现与验证，代工和封装方负责制造。由此产生三个不能混淆
的概念：

- **谁拥有架构与产品定义权**：决定长期差异化和替换权。
- **谁确认芯片收入**：决定财务报表中的收入规模与毛利结构。
- **谁拿走经济利益**：可能是云厂节省的总拥有成本，而不一定全部留在芯片供应商。

L4 主要存在三种商业路线：

| 路线 | 客户与销售方式 | 收入形态 | 主要价值捕获者 |
|---|---|---|---|
| **外售通用加速平台** | 向多家云厂、AI Lab、企业销售芯片、板卡或系统 | 产品收入，可附带软件与服务 | 平台所有者 |
| **云厂自有 XPU** | 云厂自用，并可作为云实例向第三方开放 | 对云厂体现为折旧与云服务收入 | 云厂首先捕获 TCO 优势 |
| **定制 ASIC 合作** | 客户与设计合作方联合定义，多代开发 | 可包含 NRE、IP费、产品收入或利润分成 | 客户、设计合作方与制造环节共同分享 |

**定制 ASIC 不能统一按“轻资产授权模式”估值。** 不同合作方可能只收设计服务费，也可能采购
晶圆并以芯片产品形式向客户销售；后者收入更大，但其中包含较多制造成本，收入增长不必然
带来与外售 GPU 相同的毛利率。

同样，**高终端芯片金额不等于高 L4 利润留存**。外售平台若拥有软件生态、系统标准和品牌，
能把客户的切换成本转化为毛利；定制方案的性能/成本收益则往往由大客户以采购议价和内部
TCO 节省的形式拿走。判断价值捕获要看增量毛利与现金流，而不是只看芯片 ASP 或收入规模。

## 三、Fabless 的“轻资产”边界

Fabless 不拥有晶圆厂，但绝不等于没有供给约束：

- **物理供给约束在下游**：先进制程晶圆、封装和关键材料决定可交付数量。
- **L4 自身有设计吞吐约束**：架构、验证、物理设计、编译器和内核工程师不能短期复制。
- **流片是高成本、低容错的离散事件**：一次延期或重流片会把收入曲线整体后移。
- **产能配置本身是竞争力**：能否提前锁定合适的制造资源，取决于规模、预测能力和供应商关系。
- **系统爬坡需要软硬件协同**：芯片出厂不等于客户已经形成可计费算力。

所以，L4 的资本开支通常不是最有信息量的指标，但**研发效率、流片成功率、量产爬坡、库存与
采购承诺**都很重要。不能因为它是轻资产公司，就忽略产品周期和供应链风险。

## 四、工作负载必须拆开：训练、后训练和推理不是一个市场

“AI 加速器份额”如果不分工作负载，信息含量很低。至少拆成四类：

| 工作负载 | 核心目标 | 更看重什么 |
|---|---|---|
| **预训练** | 在最短时间内完成大规模模型训练 | 可编程性、稳定性、集群有效利用率、调试效率 |
| **后训练** | 微调、强化学习、蒸馏、合成数据 | 算法迭代速度与批量计算效率的平衡 |
| **在线推理** | 满足延迟与服务质量约束 | 单 Token 成本、利用率、延迟、软件调度 |
| **离线/批量推理** | 最大化吞吐并降低成本 | 性能/功耗、量化效率、持续高利用率 |

### 训练侧

训练不是只能由 GPU 完成。只要芯片具备所需精度、算子、编译器和大规模同步能力，ASIC/XPU
同样可以训练。GPU 的结构性优势在于：研究范式变化快、错误成本高，客户愿意为成熟工具链、
可观测性、调试能力和广泛兼容性支付“灵活性溢价”。

因此，训练 ASIC 最容易成功的条件是：

- 客户拥有巨量且持续的训练负载；
- 模型架构和核心算子相对稳定；
- 客户可以控制编译器、框架与集群调度；
- 节省的长期 TCO 足以覆盖多年研发、流片与迁移成本。

### 推理侧

推理通常更容易形成稳定、可重复的工作负载，所以定制化的经济性往往更早显现；但这不是
绝对规律。在线服务还受到动态批处理、KV Cache、延迟尾部、模型路由、故障恢复和利用率影响，
软件栈并不比训练“天然简单”。

正确表述应是：

> **ASIC 通常先在规模大、稳定性高、利用率可控的推理负载中取得优势；当训练负载也满足这些
> 条件时，ASIC 同样可以进入训练。**

## 五、ASIC 不是“一个模型一颗芯片”

主流数据中心 ASIC/XPU 是**领域专用但可编程**的加速器，不是把某个模型权重或某一代模型
硬编码进硅片。一颗芯片能否高效运行新模型，取决于三层适配：

1. **硬件能力**：支持的精度、矩阵/向量运算、片上存储、数据流和并行方式；
2. **编译器与运行时**：能否把模型计算图映射、融合并调度到硬件；
3. **模型级优化**：量化、并行策略、算子内核、缓存布局和服务调度。

新一代模型通常只需要重新编译和软件优化，不需要重新设计芯片。只有当新模型长期改变了核心
计算模式，例如精度、稀疏性、路由方式或数据复用规律发生显著变化，下一代芯片才值得针对它
重新取舍。

模型适配要分三个等级：

| 等级 | 含义 | 投资上的读法 |
|---|---|---|
| **能运行** | 算子完整、数值正确 | 只证明兼容，不证明商业竞争力 |
| **能规模部署** | 稳定、可观测、可调度 | 证明进入生产环境 |
| **达到领先 TCO** | 在真实负载下利用率与成本有优势 | 才证明芯片形成经济价值 |

把“模型成功跑通”直接等同于“替代 GPU”，是最常见的证据跃迁错误。

## 六、核心经济学：比较的是有效算力，不是峰值算力

芯片规格表给的是理论峰值，客户购买的是在真实工作负载下能够持续交付的有效算力。可用下面
这个长期框架：

> **有效算力 = 峰值算力 × 软件效率 × 系统扩展效率 × 利用率 × 可用率**

> **单位任务成本 =（芯片与系统折旧 + 能源 + 运维 + 软件迁移成本 + 闲置成本）÷ 有效任务量**

由此得到五条稳定结论：

1. **峰值 FLOPS 不是充分指标**：软件效率或利用率低，纸面领先无法转化为客户价值。
2. **便宜芯片不必然有低 TCO**：迁移、调试、闲置和故障成本可能吃掉硬件差价。
3. **GPU 的溢价来自选择权**：客户为未来未知模型和快速迭代买保险。
4. **ASIC 的优势来自规模摊薄**：固定研发和迁移成本必须由足够大的稳定负载分摊。
5. **客户内部芯片的利润不一定出现在芯片分部**：它可能表现为云服务毛利改善或单位算力成本
   下降，因此不能只从外部芯片收入估算 ASIC 的经济价值。

判断定制化是否合理，可以用一个简化的 make-or-buy 门槛：

> **预计全生命周期节省的计算成本 > 芯片研发/流片成本 + 软件迁移成本 + 延期失败概率损失
> + 牺牲灵活性的机会成本**

规模越大、负载越稳定、内部软件能力越强，越容易跨过这道门槛。

## 七、技术演进的长期方向

### 1. 低精度与专用化继续提高

训练和推理会持续使用更低精度与更多专用数据格式，以减少单位任务的计算和能耗。但精度下降
受模型质量、数值稳定性和软件支持约束，不能把理论低精度算力直接当成可用性能。

### 2. 软硬件协同的重要性上升

随着单颗芯片的改进越来越难，性能提升更多来自编译器、内核、并行策略、模型结构和硬件共同
优化。芯片公司逐渐从卖“器件”变为卖“计算平台”；云厂则利用对模型和负载的可见性，反向
定义芯片。两条路线会长期共存。

### 3. GPU 与 ASIC 逐步趋同，而非一方消灭另一方

GPU 会加入更多专用单元来提升效率，ASIC 会增加可编程性来延长适用寿命。竞争焦点逐渐从
标签转向：谁能在足够广的工作负载上持续提供最低单位成本，同时不牺牲开发速度。

### 4. 产品迭代速度本身成为壁垒

先进芯片的设计和制造周期很长，而模型变化很快。能够维持稳定架构、兼容软件并按计划推出
新一代产品的公司，会形成客户规划和供应链上的复利。一次领先不等于平台领先，连续多代兑现
才是硬证据。

## 八、护城河判据：先看平台，再看单颗芯片

本层不存在一个适用于所有公司的统一护城河排序。外售 GPU、云厂 XPU 和定制 ASIC 合作方的
壁垒来源不同，应分别判断。

### A. 外售通用加速平台

按证据强度从硬到软：

1. **软件与开发者锁定深度**：迁移到其他硬件需要改多少代码、重做多少验证，性能损失多少。
2. **真实工作负载的有效性能**：不是单项基准，而是训练时间、Token 成本、稳定性和利用率。
3. **跨代兼容与迭代可信度**：客户能否沿用软件和运维体系，产品能否准时放量。
4. **系统级交付能力**：芯片、软件、整机与运维能否作为一个可部署平台工作。
5. **客户广度与需求多样性**：客户越分散，单一云厂自研造成的冲击越小。
6. **研发规模与现金流飞轮**：领先收入能否持续转化为更大的软硬件研发投入。
7. **用资产负债表锁定需求与供应**：对客户、新兴云厂与上游供应商的股权投资、算力平台
   合资与表外载体、承购与担保安排、长约与产能预付。

第 7 条是**当下最活跃的竞争手段，也是最容易被误读为护城河的一条**，所以单独说明：

- 它确实产生真实的经济效果——提前锁定紧缺的制造与存储产能、把新增算力需求绑定到自家
  架构、在客户融资能力不足时替客户跨过资金门槛。
- 但它**同时也是订单质量的折价项**。由供应商自身融资安排支撑的订单，与客户用自有现金
  下的订单不是同一种东西：前者把客户的信用风险搬到了供应商的资产负债表上，且在需求回落
  时两端同时受损。**同样规模的 backlog，融资占比上升就是质量下降。**
- 因此正确的读法不是"谁投得多谁更强"，而是两个方向一起看：**这个手段在四家之间怎么
  分布**（从"股权+承购+担保的全谱"到"只做上游产能预付"是完全不同的位置），以及
  **arms-length 订单是否同步增长**。只有后者也在增长，前者才是护城河而不是杠杆。
- 它与 L2 云厂的 capex 资金结构是同一个问题的两半：那边问"买方的钱从哪来"，这边问
  "卖方替买方垫了多少"。两边同时恶化才是系统性信号，单看一边会得出相反结论。

软件生态不是静态资产。它一方面会因库、人才和安装基数形成复利，另一方面也可能被开放编译
层、框架抽象或新模型范式降低锁定。应监测**迁移成本的方向**，不能只统计开发者数量。

### B. 云厂自有 XPU

其壁垒不在于向全市场销售，而在于垂直整合：

1. 是否拥有足够大的自有与云客户负载；
2. 是否能够看到未来模型和服务需求，从而提前定义芯片；
3. 是否控制编译器、运行时、调度和数据中心部署；
4. 是否能把芯片效率转化为云服务价格、毛利或可用算力优势；
5. 是否连续多代部署，而不是一次性实验项目。

自有 XPU 的天花板不是“只能跑自家模型”。它可以在自家云里服务第三方模型和客户；真正的
边界是客户是否愿意进入该云生态、软件兼容是否足够，以及云厂能否提供稳定容量。

### C. 定制 ASIC 设计合作方

按证据强度从硬到软：

1. **同一客户连续多代合作**：证明设计、验证和量产能力被反复认可。
2. **从流片到量产的成功记录**：设计赢单只有在成功量产后才产生经济价值。
3. **可复用的 IP、设计流程与先进节点经验**：决定项目速度、成本与重流片风险。
4. **客户和项目组合**：更多客户降低集中风险，但过多并行项目也会稀释工程资源。
5. **产品收入向毛利和现金流的转化**：收入规模大但利润留存低，不构成强价值捕获。

定制关系的切换成本主要来自时间、验证和项目风险，不是客户永远不能更换供应商。客户也可能
内部化更多设计环节、引入第二供应商，或把下一代项目交给其他合作方。因此，多代延续比单次
设计赢单重要得多。

## 九、GPU 与 ASIC 的长期竞争框架

两条路线更可能长期共存，而不是零和替代：

- **未知、变化快、客户分散的负载**更适合通用平台；
- **规模大、稳定、由单一客户控制的负载**更适合定制芯片；
- 云厂会同时采购外部 GPU 和部署自有 XPU，以平衡上市速度、灵活性、成本和供应安全；
- GPU 的绝对收入可以继续增长，同时在总加速计算中的份额下降；
- ASIC 收入增长也不自动等于设计合作方获得同等利润增长，部分收益会留在云厂。

因此不要用单一“ASIC 渗透率”直接推导个股。至少同时回答：

1. 渗透的是训练、后训练还是推理；
2. 替代的是新增需求还是存量 GPU；
3. 芯片由谁设计、谁确认收入、谁承担制造成本；
4. 客户节省的 TCO 有多少转化成供应商毛利；
5. GPU 厂商是否通过降价、提高性能或软件优化重新缩小差距。

## 十、从设计赢单到利润：证据有明确等级

定制芯片和新加速平台都要经历较长的兑现链条：

> **架构定义 → 设计赢单 → 流片 → 样片运行 → 客户验证 → 小规模部署 → 量产爬坡 →
> 第二代续约**

证据强度依次上升：

| 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 潜在客户/项目管线 | 市场兴趣 | 赢单、收入 |
| 设计赢单 | 客户选择进入开发 | 流片成功、量产规模 |
| 成功流片/样片运行 | 硬件基本可用 | 客户采用、单位经济性 |
| 客户验证 | 接近部署 | 放量速度、最终份额 |
| 量产收入 | 项目开始兑现 | 项目持续性、下一代地位 |
| 连续两代量产 | 合作关系与流程可复用 | 永久锁定 |

**连续两代量产**是判断定制 ASIC 护城河最重要的拐点。任何只停留在“参与设计”“进入管线”
的表述，都不应直接计入长期收入。

## 十一、收入与利润的结构化分解

先给一条**跨两条路线通用**的分解式。外售平台与定制 ASIC 的收入形态不同，但两者卖的都是
"每一单位部署算力里的芯片内容"，所以可以写成同一个式子：

> **XPU 收入变化 ≈ 部署算力规模 × 每单位算力的 XPU 内容价值 × 该厂商拿到的份额
> ＋ 系统/软件附加 − 代际交付延期与可达市场约束**

这个式子的用处不是估算，是**保证分析不漏项、也不重复问同一件事**。五项各自对应一个可以
独立证伪的问题：

| 分解项 | 要问的问题 | 最有信息量的读数 |
|---|---|---|
| 部署算力规模 | 这一层的周期位置在哪 | 订单承诺与已出货收入的差（book-to-bill）、能见度年限；以及**已装机存量的利用率与租金**——它决定订单能不能持续 |
| 每单位内容价值 | "AI 主 Beta"的前提还成不成立 | 每 GW / 每机架的芯片内容与 ASP 方向、买方 capex 里的硅含量占比、毛利能否传导上游涨价 |
| 份额 | 订单在厂商之间怎么转移 | 具名客户/实验室的部署归属与转移方向、客户结构广度与集中度 |
| 系统/软件附加 | 平台价值是否高于裸芯片价值 | 交付形态深度（裸片 / 板卡 / 整机架 / 全栈打包）与客户是否按该形态采纳 |
| 交付与可达市场 | 已拿到的订单能不能变成收入 | 代际量产时点的变化、爬坡是否受供应约束、单位任务成本改进是否在真实负载上兑现、出口许可 |

**两条常见的读错**：

- **把"部署算力规模在涨"直接读成"该厂商收入会涨"**。中间隔着两个乘数（单位内容价值、
  份额），任何一个下行都可以抵消规模增长。第二项尤其容易被忽略——存储、先进封装与电力
  同时在涨价时，同一个 GW 里留给芯片的钱可以是缩小的。
- **把交付延期读成需求问题**。第五项是独立的：订单、内容价值与份额可以全部完好，而一次
  流片延期或封装配额不足就能把收入曲线整体后移一到两个季度。Fabless 的季度波动多数出自
  这一项，不是前四项。

对外售平台，把上式展开：

> **收入变化 ≈ 出货量 × 单位内容价值 + 软件/系统附加收入**

> **利润变化 ≈ 收入变化 × 增量毛利率 − 研发与市场投入变化**

对定制 ASIC 合作方：

> **收入变化 ≈ NRE/IP 收入 + 量产芯片收入 × 项目放量 − 项目延期/取消**

> **利润变化 ≈ 设计利润 + 产品毛利 − 并行项目研发投入 − 重流片与爬坡成本**

长期跟踪时，应把以下读数分开：

- **计算芯片收入与公司总收入**：避免其他业务掩盖核心趋势；
- **产品收入与NRE/IP收入**：二者持续性和毛利不同；
- **收入增长与增量毛利**：收入高增长可能只是制造成本穿透；
- **当代产品与下一代项目**：当期放量不代表下一代仍在位；
- **单一客户增长与客户组合改善**：前者提高弹性，后者提高持续性。

## 十二、投资命题与证伪条件

知识库应输出可证伪命题，而不是“AI 长期增长”这类无法操作的结论。

| 长期命题 | 支持证据 | 证伪信号 |
|---|---|---|
| 通用 GPU 保持开放市场默认平台 | 新模型优先支持、跨云可用、迁移成本高、多代准时交付 | 头部客户普遍先在其他架构开发，迁移性能差距消失 |
| 自有 XPU 持续扩大经济价值 | 多代部署、第三方模型采用、云服务毛利或单位成本改善 | 芯片只内部试用、利用率低、下一代取消或明显延期 |
| ASIC 从推理扩展到部分训练 | 稳定训练负载量产、编译器与大规模部署成熟 | 只能跑窄场景，研究变化导致频繁回退到 GPU |
| 定制合作方形成跨代客户锁定 | 同一客户连续两代以上量产，毛利和现金流同步增长 | 项目只停留在管线，客户换供应商或内部化设计 |
| 平台价值持续高于裸芯片价值 | 软件/系统附加收入、客户迁移成本与有效性能保持优势 | 竞争对手通过开放软件层实现近似性能且迁移成本显著下降 |

### common 与 relative 必须分开

- **common 命题**：AI 计算总需求增长、低精度采用、云厂提高自研比例。
- **relative 命题**：哪家拿到多代项目、哪家有效性能领先、哪家把收入转成更多毛利。

总需求增长可以让多条路线同时增长，不能仅凭 common 证据判断个股胜负。反过来，一家公司
份额下降也不一定收入下降，必须同时看总市场扩张速度。

## 十三、风险的时间尺度

| 风险 | 典型时间尺度 | 说明 |
|---|---|---|
| 客户 Capex 与库存调整 | 1-8 个季度 | 护城河不变，订单仍可快速波动 |
| 产品延期、重流片、良率爬坡 | 1-6 个季度 | 对单代收入影响直接 |
| 出口限制与市场可达性 | 即时至数年 | 可在技术地位不变时削减可服务市场 |
| 客户自研与供应商切换 | 2-5 年 | 通常在下一代设计周期兑现 |
| 软件生态弱化 | 多年，但可能出现拐点 | 先表现为迁移成本下降，再表现为份额变化 |
| 计算范式改变 | 5 年以上，路径不确定 | 可能绕过既有软硬件优势 |

**不能用“护城河长期稳定”推导“盈利也稳定”。** L4 产品周期短、客户采购集中，季度波动可能
远快于竞争地位变化。

## 十四、常见误判

- **把 GPU、XPU、ASIC 当成互斥品类。** XPU 是统称，ASIC 是定制程度，现代产品处在连续谱。
- **把 ASIC 理解成一代模型一颗芯片。** 主流数据中心 ASIC 可运行多个模型；模型变化首先对应
  软件适配，而不是重新流片。
- **把“能跑模型”当成“具备商业替代能力”。** 真正门槛是规模部署后的有效性能、利用率和 TCO。
- **断言 ASIC 只能替代推理。** 推理通常更早，但稳定、巨量的训练负载同样适合定制化。
- **把 ASIC 成功等同于 GPU 失败。** 总计算需求可能增长得更快，两条路线可以同时扩大收入。
- **把云厂 XPU 当成只能服务自家模型。** 它可以在云内向第三方客户开放，边界是云生态和软件兼容。
- **把定制 ASIC 供应商都按授权模式估值。** 必须先确认收入确认方式、制造成本承担者和增量毛利。
- **把设计赢单直接计入远期收入。** 流片、验证、量产和第二代续约是不同证据等级。
- **用峰值 FLOPS 排序。** 客户购买的是有效算力和单位任务成本，不是规格表。
- **把高毛利当成永久护城河。** 高毛利是定价权的结果；要追问客户为何不能迁移或压价。
- **用公司资本开支判断 Fabless 景气。** 更有信息量的是研发效率、采购承诺、库存、量产节奏和
  下游客户的计算预算。
- **把长期好赛道等同于任何价格都值得买。** 结构分析决定盈利持续性，估值和预期决定股票回报；
  二者必须在不同模块中处理。

## 十五、给 `structure_analyst` 的最小输出模板

分析任一 GPU/XPU/ASIC 公司时，至少回答以下问题：

1. **路线**：外售平台、云厂自有 XPU，还是定制 ASIC 合作方？
2. **工作负载**：收入主要对应训练、后训练、在线推理还是批量推理？
3. **价值捕获**：谁定义芯片、谁确认收入、谁承担制造成本、谁拿到 TCO 节省？
4. **证据阶段**：项目处于设计赢单、流片、验证、量产，还是第二代续约？
5. **护城河**：软件迁移成本、多代兼容、量产执行、客户关系中哪一项最硬？
6. **经济性**：优势来自峰值参数，还是已证明的有效性能、利用率与单位任务成本？
7. **common/relative**：证据说明整层需求增长，还是说明该公司相对位置改善？
8. **证伪条件**：未来什么事实出现时，当前长期判断必须下调？

只有这八个问题都有明确答案，才应把“AI 芯片设计受益”转化为可排序的投资结论。
