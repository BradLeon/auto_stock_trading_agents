## Why

系统已经能够获取财务、Consensus、区域出口等研究数值，但大部分数据仍由具体 Workflow 临时取用，缺少统一的原始快照、指标口径、修订历史和质量状态。这使历史分析难以重放，也让新增 Agent 不得不理解各数据源差异；阶段二需要把适合长期复用的低频研究数据沉淀为共享、可查询、可计算且可追溯的结构化数据平台。

## What Changes

- 明确结构化数据的产品边界：任何可数值化内容只有在绑定了实体、指标口径、覆盖期间、单位、来源和可见时间后，才可成为共享结构化观测；文档中的数字先作为带证据的候选，不因被模型识别就自动成为可信事实。
- 建立统一的结构化接入契约和来源注册表，使 Provider 适配、原始快照、标准化、质量校验与发布相互解耦；同一来源只采集一次，多个 Agent 复用同一结果。
- 将原始响应或可复现来源切片不可变保存，并将标准化观测按数据修订形成多个 vintage，支持“最新值”和“截至某时点当时可见值”两种视图。
- 建立指标与数据集语义治理，统一公司/证券、国家/地区、行业与私营公司等实体坐标，同时保留 Provider 原字段、币种、单位、财期制度和口径差异，不强行把不可比数据合并。
- 提供稳定的结构化数据产品：指标序列、横截面对比、历史时点快照、Pandas DataFrame 和受控 SQL 查询；同比、环比、滚动统计、汇率换算等派生值按明确版本的计算规则生成，不覆盖原始观测。
- 分批迁移既有来源。首批覆盖公司财务报表、defeatbeta `stock_statement`、市场 Consensus，以及已存在的台湾/韩国出口序列；后续来源通过同一契约逐步扩展。
- 明确运行时市场数据边界：ticker 股价和期权行情不进入本结构化持久层，也不建立日线副本；Agent 与 Workflow 继续按需通过 IBKR 或 yfinance 查询，并在编排层与持久研究数据组合。
- 为 OpenAI、Anthropic 等未上市实体的融资、估值、ARR 等数据提供“证据关联的结构化事件/观测”入口，允许来自公告、研报或新闻的人工/规则/模型提取候选经过核验后发布。
- 建立覆盖度、准确性、完整性、时效性和来源可用性报告，明确区分无数据、尚未发布、来源不可达、权限不足、校验失败和数据陈旧。
- 将“配置来源—校验注册—隔离采集—质量验收—发布/回滚”做成统一、可审计的运维闭环；发布门必须实际控制来源采集模式，不能只停留在手工脚本和文档约定。
- 提供由来源目录、指标注册和当前数据库覆盖动态生成的数据目录、对象说明、可用性与可复制示例，让使用者和 Agent 无需猜测当前能查什么。
- 交付面向三类角色的数据层文档：开发者文档说明设计、组件和数据流；运维文档维护来源覆盖、QPS/限流、扩源与验收规则；使用者手册说明取数、计算、分类及 Agent/Workflow 接入。
- 交付仓库内的结构化数据消费 Skill，指导可自主规划的 Agent 先发现能力、再检查质量与时点、最后调用稳定数据产品；确定性 Workflow 继续依赖 API 契约而不是依赖 Prompt。
- 采用渐进迁移：现有 Workflow 与旧数据接口继续运行，通过兼容适配和对账逐一切换；本变更不要求一次性替换所有取数逻辑，也不在首期引入外部数据库服务。

## Capabilities

### New Capabilities

- `data/structured-ingestion`: 定义结构化来源注册、原始快照、标准化观测、修订版本、证据型数值准入、数据质量与渐进迁移契约。
- `data/structured-query`: 定义面向 Agent 和研究者的指标序列、横截面、历史时点、SQL/Pandas、派生计算与血缘查询能力。

### Modified Capabilities

无。当前仓库尚无已发布的结构化数据主规范；现有 `measurement_series` / `measurement_points` 作为实现基础和兼容对象纳入新能力，而非修改既有规范。

## Impact

- 主要影响 `ats.data` 各结构化适配器、`ats.memory` 中的 measurement/ingestion 底座、`ats.data_platform` 数据产品、实体与来源配置、`ats data` 运维命令及相应测试。
- 新增来源运行注册、发布状态覆盖层、动态数据目录与仓库内 Agent Skill；发布操作默认预检，只有显式 apply 才能改变可回滚的运行状态。
- 现有财务、Consensus、区域序列和 PEAD/Chain 调用方将经历双读或双写、结果对账、消费者切换和旧路径退役四个阶段；切换前不得改变现有 Workflow 的外部行为。
- 现有 IBKR/yfinance 股价和期权运行时查询保持原状，本变更不迁移、不双写、不回填这些数据，也不承诺通过结构化 SQL/Pandas 重放其历史行情。
- 原始快照与结构化观测会增加本地存储，但首期继续采用单机、可迁移的存储方案，并通过稳定数据产品接口隔离未来 PostgreSQL、DuckDB 或 Parquet 等实现演进。
- 非结构化文档资产仍由阶段一系统管理；只有经过证据关联和准入的数值事实进入结构化层，两层通过 document/version/span 血缘连接，不复制文档正文。
- 实施期 SHALL 新增 `docs/STRUCTURED_DATA_DEVELOPER.md`、`docs/STRUCTURED_DATA_OPERATIONS.md` 与 `docs/STRUCTURED_DATA_USER_GUIDE.md`，并由 `DATA_ARCHITECTURE.md` 提供入口。
