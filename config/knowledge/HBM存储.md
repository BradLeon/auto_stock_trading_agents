# HBM / 存储子层知识库

> 供 `structure_analyst` 打底。**只写年度级不变的东西**：价值链分工、技术演进方向、
> 护城河判据。
>
> **本文不写"谁排第几"，也不写市占数字。** 那是季度级判断，由「竞争位置证据」
> （产业链证据台账，见 `docs/CHAIN_EVIDENCE.md`）用本期财报原文给出。本文提供
> **排序的依据**，不是排序本身——本子层的领先格局在一到两个季度内就可能因一次客户
> 认证而改写，把排序写进这里必然过时，而打分器不会怀疑锚点。

## 一、价值链分工（谁在链条哪一环）

**DRAM 晶圆 → TSV 堆叠/键合 → 与逻辑芯片的先进封装(CoWoS) → 加速器**

利润集中在 **DRAM 良率 + 堆叠工艺 + 客户认证资格** 三处。

HBM 不是通用商品内存：它按代际与单一客户**联合定义**，所以「通过认证」不是一次交付，
而是拿到未来 1-2 年的份额。这决定了本子层的护城河形态与别处不同——**认证是资格，不是
订单**。

## 二、技术曲线（tech_tenor 的依据）

- **代际**：HBM3 → HBM3E（8/12 层）→ **HBM4（接口位宽翻倍、引入定制 base die）** →
  HBM4E。每代堆叠层数与键合难度上升，**良率是分水岭**。
- **定制化趋势**：HBM4 起 base die 走向客户定制，**加深与单一客户的绑定**——对已认证方是
  护城河加深，对追赶方是更高的进入门槛。这条趋势方向明确，但"谁被绑定"每代都可能变。
- **供给约束链**：HBM 产能同时受 **DRAM 晶圆、TSV/键合设备、CoWoS 封装位**三者约束。
  **任一环松动都会改变"紧张"叙事**——所以只看某一家的扩产公告判断供需，方法上就是错的。

## 三、护城河判据（moat_pricing 的依据）

按证据强度从硬到软：

1. **核心客户认证资格** —— **最硬**。通过认证 = 锁定 1-2 年份额；被替代 = 份额转移的
   速度快于任何产能建设。判断某家的位置，先看它在**当前世代**的认证进度。
2. **堆叠良率** —— 决定认证能否通过、以及通过后能供多少。良率是本子层最难追赶的能力。
3. **客户集中度（双向）** —— 深度绑定单一大客户既是护城河（联合定义、切换成本高）也是
   脆弱性（一次架构变更即失去）。**方向取决于绑定的是不是当期赢家**，不能一概判正负。
4. **垂直整合（存储 + 代工 + 封装）** —— 有整合能力的玩家在供给紧张期更能自主排产，
   但整合本身不产生认证资格。**较软**。

用法：这四条是**排序的判据**。本期谁领先由证据台账的读数决定——认证进展、良率表述、
ASP 与毛利率方向。

## 四、常见误判

- **证据强度依次递减：认证 > 产能 > 资本开支。** 竞争者扩产**不等于**先发方失份额；
  只有份额、认证、ASP/毛利率的**直接读数**才说明位置变化。
- **三家同时扩产 = 层级供给转松（common 命题），不是某一家的相对优势变化（relative）。**
  把前者读成后者，是本设计存在的首要理由。
- **HBM 售罄但 ASP 走平 = 稀缺溢价已被定价完。** 供不应求本身不等于定价权还在扩张。
- **"样品出货"与"量产认证"是两个阶段。** 前者是进度信号，后者才是份额资格；把送样
  当成反超，会提前一到两个季度做出错误判断。
- **国产替代（如 CXMT，非上市）冲击的是整层的定价权，不是某一家的份额。** 它没有可交易
  标的，只作为**减仓侧信号**存在。
