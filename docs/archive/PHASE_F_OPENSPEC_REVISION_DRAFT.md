### workflow/cutover-control

| 要求 | 处置 | 修订要点 |
|---|---|---|
| 每条切流边界必须有独立功能开关 | **保留** | — |
| 角色发布、审批写入与账本发布必须受各自边界控制 | **保留** | — |
| 冲突的切流配置必须在启动时 fail closed | **保留** | — |
| 读路径路由必须逐消费者依据读取资格判定 | **修改** | 研究读取按**消费者整体**路由；切换前做消费者层面的数据产品健康检查，观察期每日复查；精确 scope 路由行保留作可选的细粒度停止，不再是日常运行前提。"读取资格不得开启交易权限""原生查询必须带业务 scope"两个场景**保留** |
| 资格失效时必须执行已登记的安全停止或恢复策略 | **修改** | 迁移窗口内默认**退回旧路径**并告警；旧入口退役后才要求"停止"策略；不再要求每个 scope 一份带有效期的停止证明 |

| 切流门禁不变量必须由机器校验 | **修改** | 机器校验保留于安全底线（禁券商写、单一实盘入口、成对边界、单一调度负责人）；入口证据包、兼容性证明文件、绑定请求哈希的精确授权不再是切流前置 |
