# Design

## Context

- `observer.concept_menu` 按“该公司是否为某条命题的声明见证方”过滤。命题为空时菜单为空，抽取会退化成给利润表编目录，这就是 418 条通用财务读数的成因。
- 2026-08-20 记录的候选方向：并网接入排队与交期、机电长单能见度、项目取消/延期、液冷渗透、现场发电从应急转常规。
- 行业通行的跟踪口径（卖方电力设备与数据中心覆盖的常见做法）：订单与积压（book-to-bill、backlog 覆盖月数）、交期（变压器、燃气轮机、开关设备）、数据中心相关订单占比、项目延期与取消、电网接入排队时长、现场发电与燃料电池部署规模、液冷渗透率。

## Goals / Non-Goals

**Goals：**
- L3 有 2–4 条命题，每条在四家公司最近一季财报中至少能落下区分性读数。
- 每条命题的方向判定可复核。

**Non-Goals：**
- 不引入付费行业数据库。
- 不改截面因子与风险预算。

## Decisions

### D1. 候选命题（建议采用前三条，实施前由用户确认）

| # | 命题 | 主要维度 | 见证方 | 区分性读数举例 |
|---|---|---|---|---|
| C1 | 机电设备订单与积压是否仍在扩大，能见度是否延长 | 订单增速、book-to-bill、backlog 覆盖月数、数据中心订单占比 | VRT、ETN、GEV | “数据中心订单同比 +x%”“backlog 覆盖 n 个月” |
| C2 | 交付瓶颈是否在缓解（交期、产能） | 关键设备交期、产能扩张与投产时间 | ETN、GEV、VRT | “变压器交期从 x 周降到 y 周”“新增产能 202x 投产” |
| C3 | 项目取消或延期是否增加 | 项目取消、延期、终止成本 | 四家 | “site termination costs”“客户推迟交付” |
| C4 | 现场发电是否从应急走向常规供电 | 现场发电部署规模、合同期限、客户类型 | BE、GEV | “与超大规模云厂商签 x MW 长约” |

**建议先上 C1–C3。** 它们直接回答本层的问题，且四家公司的财报和电话会通常都会披露。C4 目前主要只有 BE 一家能给读数，先作为观察项，等出现第二个见证方再声明。

### D2. 方向判定沿用现有观察器规则

方向由读数的同比或环比变化给出；无历史可比时返回 `insufficient_history`，不当作持平。

### D3. 先回放、后声明

先用候选命题对 2026-08-20 的读数和最近一季财报做一次回放抽取，看每条命题的落点数与区分度。落点为零或全是重复通用财务数字的命题不声明。

## Risks / Trade-offs

- [ETN、GEV 的 AI 敞口不是 100%，读数混入非数据中心业务] → 命题维度要求“数据中心相关”的限定词；未限定的读数不计入。
- [只有一家公司能给读数的命题让覆盖率失真] → 每条命题至少两个见证方才声明（C4 因此暂缓）。

## Migration Plan

1. 用户确认命题清单。
2. 回放验证并报告落点。
3. 写入配置。
4. 下次层报告核对。

回滚：把 `claims` 改回空。历史观测保留，不会被删除。
