# 个人投顾系统风控体系

适用范围：股票、ETF、ADR、跨市场挂牌证券、杠杆 ETF 和已持有期权；不覆盖期货、
涡轮或其他带路径依赖的衍生品。

## 1. 风险单位

证券代码只是执行工具，硬限额作用于 `economic_entity`。系统通过
`config/risk.yaml` 的 `instruments` 将跨市场挂牌、ADR、ETF 和期权底层汇总到同一经济实体。

所有可调风控参数只有一个维护入口：`config/risk.yaml`。其中 `limits` 是全局 L1-L6
阈值，`sector_layer_caps` 是行业层上限，`option_survival` 是指派资金约束，`directive`
是状态机参数，`instruments` 是经济实体映射。`config/sectors/*.yaml` 只维护行业结构和
证券归属，加载时由中央风控配置注入层上限。

每个实体同时保留三种不可混用的口径：

- 资本权重：基础货币市值 / NAV；
- 经济 Delta：资本权重 × 产品内嵌杠杆 + 期权 Delta 名义 / NAV；
- beta 贡献：经济 Delta × 底层风险标的 beta。

产品杠杆只应用一次。杠杆 ETF 的 beta 从底层风险代码取得，不能再使用已经包含产品
杠杆的产品 beta，否则会重复放大。

所有 IBKR 本地货币市值、PnL、期权 Delta 名义、vega/theta、Reg-T 估算和情景重估，
先按 IBKR `ExchangeRate` 换到账户基础货币。汇率缺失时拒绝混算。

## 2. 交易前边际风险

统一下单闸门按顺序生成预计交易后组合并重跑确定性风控。放行不依赖 buy/sell 标签：

- `NORMAL/LIMITED`：允许在全部硬限额内消耗风险余量；
- `REPAIR_ONLY/DATA_INVALID/EMERGENCY`：必须改善至少一项已破限指标，且不得恶化其他
  指标；
- 产生新破限的交易一律拒绝。

风险向量覆盖经济实体、产业链层、beta、杠杆、现金、保证金、压力损失、事件损失和
期权指派资金。多笔订单顺序模拟，前一笔获批后的预计持仓是后一笔的起点。
股票交易后的保证金使用 IBKR 实时基线加 Reg-T 增量估算并明确标注；实际提交前仍由
券商保证金校验兜底，不能把估算值描述成 IBKR what-if 结果。

## 3. 期权生存性

短 put 同时使用四个约束，避免只看全额指派名义：

1. 全额指派名义：灾难性上限；
2. 概率加权占用：`行权价 × 合约数 × 乘数 × P(到期ITM)`；
3. P99 联合占用：仓位级 Bernoulli 正态近似并封顶于全额名义；
4. 到期结构：按精确到期日计算单日峰值，并按 `expiry_horizons_days` 提供累计资金桶。

欧式 BSM 到期 ITM 概率为 put 的 `N(-d2)`，不是 delta 的绝对值 `|N(d1)-1|`。缺少
spot/IV 时才使用绝对 delta 作为降级估算；两者都缺失则进入 `DATA_INVALID`。美式期权
可能提前指派，因此报告始终披露该模型风险。

BRK.B 的全额现金信用是当前策略的明确假设，指派层将其计入有效流动性，不在此版本
引入 haircut。

## 4. 给 Chief 的状态机

| 状态 | 含义 | Chief 可做什么 |
|---|---|---|
| `NORMAL` | 限额和数据正常 | 在剩余预算内增加、对冲或降低风险 |
| `LIMITED` | 接近限额或存在提示 | 小幅增加、对冲或降低风险 |
| `REPAIR_ONLY` | 存在已知硬破限 | 只做经交易后模拟验证的修复/对冲 |
| `DATA_INVALID` | 生存性关键数据不可估 | 降低风险、取消待执行风险单 |
| `EMERGENCY` | 回撤/日亏、流动性耗尽或灾难名义破限 | 降仓、关闭短期权、补充流动性 |

`RiskDirective` 还包含禁止增加的经济实体/产业链层、剩余风险预算和必须修复列表；
下单闸门会独立复算，Chief 的理解不能代替确定性执行约束。

## 5. 当前边界

风险引擎完整评估账户中已持有的股票和期权。当前可执行 `TradeDecision`/Trader 仍是
股票合约模型，因此期权新订单尚不能由 Chief 自动构造或提交；在增加合约唯一标识、
组合腿和 IBKR what-if margin 之前，不应把期权执行强行塞进股票订单字段。
