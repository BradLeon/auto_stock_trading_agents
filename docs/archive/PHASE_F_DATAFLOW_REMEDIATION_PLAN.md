# 数据流补齐方案：证据抽取、截面财务、Macro 新闻（2026-10-16，待审阅）

> 依据：`docs/archive/PHASE_F_10_5_PREFLIGHT_AUDIT.md` 的考察结论与 TARGET §3（数据采集由数据平台隐式完成）、§4（分析师只读 Data Products）、§12.1（Agent 不得直接调用 Provider）。本文只是方案，没有改代码、没有调模型、没有写生产数据。

## 一句话

三件事都按同一个原则改：**采集和抽取全部挪进数据平台的刷新控制器（`com.ats.data-refresh`，每小时一次），分析师只读已发布的数据。** 其中证据抽取最急：Q3 财报季已经开始（ASML 10-14、TSM 10-15 已发布），抽取开关关着，这一季的产业链证据正在漏掉。

## 一、证据抽取改成刷新控制器的定时任务

**现状**
- 产业链中性证据（`data_evidence_facts`）只来自一处：旧调度器里 PEAD 打分窗口顺带调用的 `_observe_window`。它对 PEAD 目标和观察名单（23 个名字）逐个检查「最近有没有已确认发布的财报」，有就取财报文件、用 `evidence_observer`（DeepSeek flash，走官方 API）抽取事实。
- 开关 `pead_observe_window: false`，旧调度器也没加载，所以 9、10 月一条都没有。
- 取文件的代码已经在数据层（`data/collection/evidence.py`），抽取已按文档幂等（同一文件不重复抽）。

**设计**
1. 把 `_observe_window` 的编排挪到数据层（`data/collection/evidence.py`），提供 `ats data evidence-observe` 命令。逻辑不变：财报双确认（实际 EPS + 发布日后的 8-K/公告）、按财报期守卫取文件、已抽过的文件跳过。
2. 在 `config/data/schedules.yaml` 新增一个**每日**任务 `chain_evidence_daily`，由刷新控制器经持久队列执行；在数据目录登记为一个派生来源（带请求预算），这样它和其他采集任务一样有账本、重试、健康状态。
3. 名单由配置决定，不写死：PEAD 目标与观察名单 ∪ `config/sectors/ai_hardware.yaml` 八层截面标的（去重后约 40 个）。截面里 L3/L4/L6 那些标的此前从不抽证据，这次一并覆盖。
4. 旧调度器的 `_observe_window` 保留但不再是唯一入口；`pead_observe_window` 这个开关保持你设的 `false`，不去动它。
5. **一次性补抽：** 用 60 天回看把已经发布、还没抽过的财报补上（Q3 已发布的和 8、9 月零散的），之后每日任务只看最近 7 天。

**验证**
- 测试：名单来自配置；同一文件不重抽；未确认发布的财报跳过；任务失败不影响其他名字；控制器账本记录每个名字的结果。
- 生产：先 `--dry-run` 列出将要处理的名字与财报（不取文件、不调模型）给你看；批准后补抽一次，报告新增证据条数与实际模型费用；再启用每日任务，观察一次 tick。

**代价**：每份财报文件按窗口分段抽取，大约 2–6 次 flash 请求。补抽约 30–40 份文件，预计 60–200 次请求；每日任务只在有新财报时才调模型。费用以运行记录里的实际用量为准。

## 二、补齐 23 只截面标的的受治理财务包

**现状**
- 平台里有完整财务的只有 7 只：AMD、AMZN、KLAC、MRVL、MSFT、NVDA、TSM。
- 缺的 23 只：GOOG、META、CRWV、SPCX、VRT、ETN、GEV、BE、COHR、LITE、AAOI、CRDO、AXTI、AVGO、MU、SKHY、005930.KS、SNDK、STX、WDC、ASML、AMAT、LRCX。
- 刷新控制器里**没有任何财务采集任务**，现有数据都是此前手动或按需补的。Sector 的截面读取已是 `platform` 模式，缺包就显式缺失，不回退到供应商。
- 来源优先级（代码里已定）：defeatbeta 报表 → yfinance 报表 → SEC companyfacts；三个来源都已登记（shadow 模式，数据可被消费者读到）。适配器多数一次只接受一个标的。

**设计**
1. **刷新控制器支持在一个任务里列出多个标的**（`entities:`，每个标的一条队列任务、各自记账和重试），避免像共识那样写 11 份几乎一样的条目。名单同样来自配置（截面标的 ∪ PEAD 名单）。
2. **先做覆盖探针，不发布：** 对 23 只 × 3 个来源各取一次、只做质量门判断，产出覆盖矩阵（哪只能从哪个来源拿到完整季度包）。预期：美股和在 SEC 报表的标的（含 ETN、ASML 的 20-F 年报）大多可得；005930.KS 与 SKHY 只能靠 yfinance；SPCX 今年 5 月才上市，季度历史很短。
3. 按矩阵为每只标的选定来源，新增每周任务 `company_financials_weekly`（财报季后自然拿到新季度）；质量门拒绝的照常进隔离区并显式缺失。
4. 读取侧不改：截面继续用现有「完整报表包」选择逻辑。

**验证**
- 测试：多标的任务逐个入队、单个失败不连坐、预算按来源计；覆盖探针不写发布表。
- 生产：覆盖矩阵给你过目 → 批准后首次采集 → 报告 30 只截面标的的覆盖率（目标：能拿到的全拿到，拿不到的列明原因）。

**代价**：纯数据采集，不调模型；三个来源各有请求预算与限速。

## 三、Macro 新闻改为读已准入文档

**现状**
- 宏观评审按 `config/macro.yaml` 的主题查询（FOMC/降息预期、CPI/PCE、ISM/PMI 等）**在分析过程中实时调用 Tavily 网页搜索**，违反 §12.1-3。
- 数据平台里目前**没有宏观类文档**：已准入的都是公司新闻、财报纪要、SEC 索引、行业通讯。

**设计**
1. 把同样的主题查询挪成数据平台的采集任务 `macro_theme_news_daily`：Tavily 结果作为文档进入准入流程（来源、发布时间、URL 去重、正文完整性），按主题打标签（例如实体 `MACRO:fed`、`MACRO:inflation`），文档类型 `macro_news`。
2. Macro 评审改为读 `admitted_documents(entities=MACRO:*, document_types=macro_news, 近 21 天)`，不再导入 websearch；没有材料时明确写「无已准入宏观材料」，不临时去搜。
3. 架构守卫加一条：分析师模块不得经任何路径到达 `data/websearch`。
4. 之后可以把美联储新闻稿、BLS 发布等官方来源加成同一类文档；不在本次范围。
5. **宏观指标（FRED/yfinance 运行时拉取）这次不迁**，在 TARGET 里登记为有意偏离（代码注释已写明理由）；是否迁入持久层，留作后续单独决定。

**验证**
- 测试：Macro 不再导入 websearch（守卫）；无材料时输出明确缺口；有材料时引用带文档版本。
- 生产：采集任务跑一次，报告每个主题准入的文档数；随后 Macro 首跑（属于 10.5 的 Macro 段）读这些文档。

**代价**：每日每个主题约 1–2 次搜索请求（Tavily，非模型）。

## 三、Macro：新闻与定量指标都已迁移

- **新闻（`macro_theme_news_daily`）：** `ats data macro-news-collect`。`config/macro.yaml` 的主题查询搬进采集任务，结果作为 `partial` 的不可变文档版本入库（实体 `MACRO_<主题>`，按 URL 去重；正文不足 200 字、没有 URL、超出 21 天窗口的丢弃并计数）。Macro 只读已准入文档（`macro_inputs.admitted_news`），没有材料就写「无已准入宏观材料」。**分析过程不再检索外部**，架构守卫加了测试：数据产品模块不得引用搜索模块。
  - 已运行一次：货币政策主题 8 条结果全被丢弃（最近的 FOMC 新闻是 9-16，超出 21 天），其余主题入库 4–10 条不等。
- **定量指标（`macro_series_daily`）：** 新数据源 `macro_series_feeds` / 数据集 `macro_series` / 实体 `US_MACRO`，25 个序列（FRED、行情收盘价、CNN 恐惧贪婪），一次性回填 11 年共 **35,909 条观测**，之后每天重读最近 120 天捕捉修订。Macro 评审改读存下来的序列（`macro_inputs.macro_snapshot` / `macro_series_histories`），缺口和过期在 `notes` 里点名。
  - **与旧的实时拉取对账（22 个字段）：** 利率、通胀、就业、信用类 13 个完全一致；油、金、美元、标普、纳指有 0.1–0.2% 的取数时点差；VIX（16.46 对 15.93）、标普/纳指涨跌幅、恐惧贪婪（30 对 29）差异稍大。原因是 VIX 存的是 FRED 的上一交易日收盘，旧代码取的是盘中价；其余是取数时刻不同。**这是一处有意的口径变化**：评审读到的是已收盘数据，不再是盘中数据。
  - 过期判定把发布滞后算进去：CFNAI、核心 PCE 最新是 8 月、生产率是 Q2 都属正常，不报过期。
- **没有迁的：** FactSet 与区域出口本来就在平台里，不动。
