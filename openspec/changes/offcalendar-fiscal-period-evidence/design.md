# Design

## Context

- **财期比对：** `admission._period` 用 `fiscal.parse_label` 把标签解析成（财年, 季度）。目标财期为空时直接判 `period_unresolved`。
- **目标财期的来源：** 来自财报事件。对日历财年公司，期末日期能直接换算；ORCL（财年截至 5 月末）与三星（三星的“2026 年第 3 季度”对应日历 Q3，但披露文档的命名与 PEAD 事件的财期标签不一致）缺少换算规则。
- **抽取顺序：** `evidence-observe` 先调模型、后保存。保存时 `stores/unstructured/platform.py` 才检查文档是否为已发布版本。

## Goals / Non-Goals

**Goals：**
- 两家公司的最近一季财报能通过准入，并抽出观测。
- 未通过准入的文档零模型请求。

**Non-Goals：**
- 不改准入的其他检查项（身份、类型、正文质量）。

## Decisions

### D1. 财年结束月作为公司元数据

财年结束月是公司的固有属性，登记为 `fiscal_year_end_month`（默认 12）。

换算规则：以报告期末日期 + 财年结束月推出（财年, 季度）。
- 财年标签取“财年结束所在的日历年”，这是美股惯例，ORCL 的 FY2026 截至 2026-05-31。
- 季度按财年起始月起算。

**备选方案：** 为每家公司手写期别映射表。放弃原因：每季都要维护，正是 `config/pead/*.yaml` 中 `fiscal_label` 过期的老问题。

### D2. 三星的标签对齐

三星财年即日历年，问题在于文档标签和事件标签的写法不一致。在解析层统一规范：财年、季度两个字段都按数值比较，不比较原始字符串。

### D3. 抽取前置准入检查

`evidence-observe` 在构造模型请求前先查询文档版本的准入状态：
- 未准入或被隔离：直接记 `skipped_unadmitted`（附隔离原因），不调用模型；
- 已准入：按原流程处理。

保存时原有的检查保留，作为第二道防线。

## Risks / Trade-offs

- [财年结束月登记错误，导致财期错一个季度] → 回放 ORCL 最近四季、三星最近四季，与公司公告的财期标签逐一核对。
- [其他公司也有非 12 月财年而未登记] → 准入的 `period_mismatch` 仍会拦下；在缺口报告中列出这类公司，提示补登记。

## Migration Plan

1. 登记两家的财年结束月。
2. 修解析并做回放核对。
3. 前置准入检查。
4. 恢复抽取名单。
5. 观察一次真实运行。

回滚：把两家重新放回排除名单。
