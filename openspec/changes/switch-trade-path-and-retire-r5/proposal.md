# Proposal

## Why

**投资与风险上的问题：**

- **研究和决策脱节。** 六个研究分析师每天在新路径上产出，但主理人只在你手动运行时才决策，而且决策上下文仍从旧表拼出来。主理人看到的可能不是当天研究快照里的那一版：旧表里留着降级或过期的行业配置，新快照里是重跑后的版本。决策可以追溯到“哪一版研究”，这一点目前只在隔离环境被证明过。
- **账户没人对账。** 旧调度器删除（faeac82）时，主理人每日决策和书记员（Clerk）每日对账两项没有迁移。现在没有任何进程每天核对真实持仓、成交和资金：你在 TWS 里的手动交易没有进账本，绩效与归因无从计算，下一轮主理人和风控读到的“组合状态”也没人保证是新的。
- **退役卡在这里。** 退役 change `retire-legacy-and-migration-tooling` 把交易侧的 R5 条目（共 20 条：读取侧旧表、旧决策写入与入口、交易侧与 10-27 转入的切换期工具、与 Chief 共用的读路由与资格机制）登记在“交易路径切换”这道门后面，但目前没有 change 承接这道门。不切换，新旧两套读路径和一整套迁移期控制面就会一直并存。

**为什么现在：** 研究侧已在 Dispatcher 上稳定运行，新交易实现（不可变修订、多轮风控、审批绑定、Clerk 账本）在隔离环境通过了 22 项订单追溯核验。剩下的是在生产上切过去，并把实盘锁定**原样保留**。

**本 change 不解锁实盘。** 切换完成后，系统每个交易日完整走一遍“研究快照 → 主理人 → 风控 → 你在命令行审批 → 执行前检查”，在券商交接点被实盘锁拒绝，不下任何订单（含 IBKR Paper）。你得到的是一份每天都有、可追溯的“系统本来会怎么做”的记录，用它来判断以后是否值得解锁实盘。解锁需要你另行明确授权，前置条件在 design.md D9 单列。

## What Changes

- **交易路径人工核验门 T0**（类比研究侧 G0）：
  - 在隔离环境（无网络的模拟券商）核验完整链路：决策输入、多轮风控、审批绑定、执行前检查、Clerk 对账与重建、单活与回退；
  - 在生产上做只读核验：用真实账户跑一次 Clerk 只读演练，用真实研究快照渲染一次主理人上下文给你看；
  - 自动证据由我准备，结论由你签。未通过前不做任何生产切换。
- **切换前的实现改动**（在隔离环境验证后再上线）：
  - 主理人上下文改为只从研究快照的投影渲染，交易历史与绩效改经内部状态读取；
  - 决策记录的读取方改读审计表，旧表镜像写保留到观察窗口结束，作为回退的安全垫；
  - Boss 审批改为在命令行异步完成：定时决策跑到待审批就暂停并结束进程，你之后用 `ats approval` 列出、查看、批准、驳回修改或拒绝（绑定修订 hash，三种动作：批准；驳回并附修改意见，由主理人重新修订后再审；直接拒绝，周期终结）。只有需要下单、且已通过风控的修订才会送到你面前。飞书审批回调暂缓：一是以后不一定用飞书，二是经 Cloudflare 隧道的回传经常失败。待审批时只发一条不带链接的单向提醒。批准时先刷新快照、确定性重审同一修订，再立即执行，以满足 60 秒的快照时效；
  - 新增“已批准未执行（实盘锁定）”终态：演练或锁定下被批准的决策不再被记成“已执行”，命令行在批准前写明“批准后不会下单”；
  - Dispatcher 新增两个交易路径工作流：主理人每日决策、Clerk 每日对账，只在交易日触发、各自幂等；在时间表里先不启用，S4、S5 才启用；
  - Dispatcher 同一进程内的 IBKR 连接使用互不冲突的 client_id；新的每日周期开始时，前一日仍待审批的周期转为失效；
  - 实盘授权记录增加来源核实状态。`LIVE-X` 经调查很可能是开发时的测试误写，你确认后追加作废记录；在此之前，实盘门一律拒绝它。
- **生产切换**（每一步都需你批准，按顺序做）：
  1. Chief 改读；
  2. 决策记录读取方迁移；
  3. 审批与账本在同一次发布里成对切到审计表；
  4. 启用 Clerk 每日对账；
  5. 启用主理人每日决策。

  之后进入 5 个交易日的观察窗口：有明确的停止条件，回退方式是停用两个工作流，再 `git revert` 读取方切换的提交。
- **R5 接续**：观察窗口通过、你确认后，按依赖顺序退役：
  1. 读取侧旧条目；
  2. 写入与入口侧旧条目；
  3. 切换期工具：包括交易侧切换工具，以及 2026-10-27 从退役 change 转入的原研究侧 R2 工具（批次与读路径切流、调度切换、接入核验、新旧调度去重）；
  4. 最后把读路由与资格机制收窄为“按声明的数据产品与业务 scope 读取”。

  实盘路由仲裁、实盘授权、券商写禁令属于长期的资金安全机制，**不在退役范围**。
- **BREAKING（R5 阶段，运维命令）**：
  - 删除 `ats cutover`、`ats drill`、`ats shadow`；
  - 删除原 R2 的 `ats batch`、`ats read`、`ats intake`，以及 `ats dispatch` 的 `runtime-*`、`ownership`、`ledger`、`executed`、`record-execution`、`rollback-plan`、`rollback-history`；
  - `ats journal` 的独立对账入口降为单步调试；
  - `ats live drill/rollback-drill` 保留，实盘解锁时还要用。

  具体清单见 design.md D10。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `workflow/dispatcher-runtime`：新增“交易路径工作流必须由 Dispatcher 按交易日排程”。
- `decision/approval-lifecycle`：
  - 新增“人工审批必须可在命令行异步完成”；
  - 新增“实盘锁定时已批准的修订必须以显式终态结束”。
- `execution/live-route-switch`：
  - 新增“实盘授权记录必须经来源核实后才能被采信”；
  - 修改“真实实盘切换必须由外部明确授权解锁”，写明交易路径切换及其观察窗口通过都不构成授权。
- `workflow/cutover-control`（R5 完成后生效）：
  - 删除六条边界功能开关、各边界写入控制与联合边界切换三条要求；
  - 两条门禁要求收窄为只保留交易路由单活、券商写禁令与 fail closed。
- `data/target-dataflow-assurance`（R5 完成后生效）：
  - 新增“消费者必须按声明的数据产品与业务 scope 读取”；
  - 删除迁移期的逐消费者读取资格与资格账本两条要求。

## Impact

- **代码**：
  - `agents/chief/assemble.py`、`graph/chief.py`、`decision/state.py` 与 `decision/repository.py`；
  - `memory/store.py` 的决策读取、`runtime/cli.py` 新增 `ats approval` 命令组（复用现有的暂停/恢复机制）、`channel/` 的上下文、`execution/live_authorisation.py`、`broker/ibkr.py` 的连接标识；
  - `runtime/dispatcher_daemon.py` 与 Dispatcher 任务注册；
  - R5 阶段删除 design.md D10 所列模块。
- **配置**：
  - `config/workflow/research_schedules.yaml`（或新建交易路径时间表，见 design.md D5）、`workflow_owners.yaml`；
  - R5 阶段更新 `legacy_retirement.yaml`、`freeze_surface.yaml`、`target_dataflow_coverage.yaml`。
- **运行**：
  - `com.ats.dispatcher` 将连接 TWS，并调用主理人和风控的模型；
  - 每个交易日新增一次决策的模型请求（实测数在 T0 中记录），外加一次待你命令行审批；
  - 批准后由执行 `ats approval approve` 的命令行进程恢复执行，跑到券商交接点；
  - `com.ats.serve` 与飞书审批卡不在新交易路径上。代码保留，不退役，等你选定 IM 工具后另立 change。
- **数据**：不删除任何历史表、账本与审计记录。旧决策表在观察窗口内继续被镜像写入，R5 后停写、保留可读。
- **依赖**：
  - R5 的读路由收窄只依赖退役 change 的 R0（登记字段与门）与 R1。原 R2 已于 2026-10-27 整组并入本 change 的 R5c，不再是外部前提；
  - 本 change 归档必须在退役 change 归档之后，避免两份规格增量冲突。
- **不受影响**：
  - 实盘锁定的三道锁（生产券商提交禁用 C3、实盘路由 disabled、实盘门无有效授权）全部保留；
  - 研究侧 7 个工作流的调度与读路径不变。
