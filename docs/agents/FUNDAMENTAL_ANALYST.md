# 基本面分析师（Fundamental Analyst，PEAD 框架）

> 契约以 [`TARGET_WORKFLOW_DATAFLOW.md`](../TARGET_WORKFLOW_DATAFLOW.md) §7.2、§9.2、§9.3 为准；需求条文见
> `openspec/specs/agent/`。运维命令见 [`OPERATIONS.md`](../OPERATIONS.md)。

## 它回答什么

**市场对这家公司这次财报预期了什么；财报出来后，现实与预期差了多少、往哪个方向。**
PEAD（财报后漂移）是它的分析框架，不是一个单独的角色：财报前的准备就是**例行模式**，财报后的打分就是**事件模式**。

它只给方向、幅度、信心和可证伪条件，**不给订单、数量或风控结论**——最终交易决策和风控属于 Chief 与风控主管。

## 输入、输出与触发

| 项 | 内容 |
|---|---|
| 读什么 | 公司研究包（财务、一致预期、公告、纪要、指引、期权隐含波动等市场预期）、产业链共享事实、**信息分析师的简报**（唯一允许读的其他分析师产出） |
| 不读什么 | 行业、宏观、技术面的观点；不调用组合 pre-trade check |
| 产出 | 例行：`fundamental_expectation_update` 投影；事件：`fundamental_event_review` 投影 |
| 谁读它 | Chief |
| 代码 | `src/ats/agents/fundamental/`（`routine.py`、`event.py`、`baseline_view.py`）；打分、单位与报告在 `src/ats/agents/pead/`；财报事件流程用 LangGraph（`graph/pead.py`） |
| 单票设置 | `config/pead/<SYM>.yaml` 合并在 `config/pead/_defaults.yaml` 之上（打分维度、权重、阈值、上下游） |

## 例行模式：财报前

工作日 09:00（纽约时间）运行，依赖当天同一标的的信息简报。

1. **建立预期基线。** 下一次财报在 `config/pead.yaml` 的 `schedule.prep_days_before`（现为 3）天以内时，
   如果这一期还没有基线，就建一份：保守/中性/乐观三档预期、市场隐含预期（一致预期、期权隐含波动、
   是否已提前抢跑）、核心叙事、关注的 KPI 与可证伪条件。盘前（bmo）财报最晚在前一天建。
   基线以 `[基线 vN]` 的版本化投影发布，带完整明细（`baseline` 字段）。
2. **归类新的事实变化。** 读当天简报的每条 `fact_changes`，归为 **确认 / 否定 / 新增 / 待验证** 之一
   （分类器角色 `fundamental_classifier`；失败时规则回退并在驱动说明里标注），对有数值读数的变化发布
   预期更新投影，每条变化一份，带变化前后的值、驱动、证据引用。
3. **手动刷新基线**：财报 cutoff 之前可以重建基线（产生 `[基线 v(N+1)]`），见 OPERATIONS §3.2。
4. 数据版本没变、投影仍在有效期内（72 小时）时直接复用，不重复请求模型。

## 事件模式：财报后

日历确认财报**真的发布了**、且公告或申报材料已准入之后由事件唤醒（不按预测日期猜）。

1. **冻结基线**：在事件 cutoff 冻结财报前基线及其引用，之后到达的信息不改写它。
2. **只用正确期间的实际值**：报告期间正确且通过准入的 actuals、财报稿、指引与电话会；要求抽取绝对金额
   并标明申报币种。
3. **三类差异分列、不取平均**：实际值分别对照冻结基线、一致预期、市场隐含预期；方向不一致时保留分歧。
   只比较币种和单位一致的两个数；币种不同（例如一方已按汇率换算）或差距超出 -75%～+300% 的，记为
   **不可比**（`not_comparable`）并写明原因，不当作超预期或不及预期。
4. **Surprise Scorecard**：按单票配置的维度与权重打分（默认维度：毛利率、前瞻指引、营收、EPS、核心业务
   增速、订单、电话会语气）。基线有维度但抽取不到逐维度读数时，重试一次；仍然没有就**拒绝打分**，
   不出一张全零的打分卡。
5. **新版本不覆盖旧版本**：电话会迟到时产出新版本，旧版本保留可查回。最新的 `published` 版本生效；
   被判无效的版本标为 `failed` 并备份，台账不删。

`FundamentalEventReviewPayload` 主要字段：`direction`（-1/0/1）、`magnitude`、`confidence`、`scorecard`、
`guidance`、`narrative`、`falsifiable_conditions`、`actuals`、`baseline_ref`、`baseline_as_of`、`comparison_basis`。

## 没有基线时

财报前没有建过基线的标的（例如基线机制上线前已发布的财报），事件评审会明确标注「无比较依据」，信心封顶
0.1。验证的是工作流本身，不是预期差。

## 常见问题

- **例行模式 `上游依赖失败`**：当天该标的的信息简报没有发布，见信息分析师文档。
- **重跑一次已有好结果的事件评审**会产生新的最新版本、覆盖旧结论；重跑后要核对产物（打分卡、读数），
  不能只看 `status=complete`。模型对同一输入的打分会有小幅浮动。
- **基线里的币种或口径混用**（例如 `$` 与 `€` 混写）会让大部分对比变成不可比，这时要修的是基线或单票配置。
