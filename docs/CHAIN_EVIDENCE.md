## 一、要解决的问题

持有 SK Hynix 押注 HBM，但 HBM 的供需平衡由 SK Hynix、美光、三星**三家共同决定**。
只读其中一家的财报，等于用三分之一的证据下注。云服务商同理：盯着 MSFT 和 GOOG，
可 AWS 和 Oracle 的资本开支指引同样定义整条链的需求。

**利润是流动的。** 但系统当前的分析单元是"股票"，不是"产业链环节的利润池"——一家
公司的财报被当成孤立事件处理，而不是对某个产业变量的一次观测。

更具体地，缺的不是"看到"，是**这两件事**：

1. 未持有的同业、客户、供应商，正在**确认**还是**反驳**我的持仓假设？
2. 一个行业利好，究竟是**共同需求扩张**（大家一起好），还是**竞争对手抢走份额**
   （我变差了）？这两者对仓位的含义完全相反。

## 二、不变式

即使以后重写实现也不能丢的几条：

1. **共同需求与相对份额必须分开记账。** 同一个事实可以同时是"行业需求正面"和"我方
   份额相对负面"。任何把两者压成单一多空分数的设计都是错的。
2. **竞争者变强 ≠ 我方变弱。** 美光扩产只证明行业供给增加。**没有直接的份额、客户
   认证或 ASP 证据时，不得推导我方份额下降。** 这条由代码执行，不交给 LLM 判断。
3. **独立性按事实来源算，不按文章数量算。** 十篇转载是一个证据簇；公司新闻稿 + 电话会
   + 财报 deck 上的同一个数字，也是一个证据簇。
4. **零结论是正确默认。** 证据不足输出 unknown，不补猜、不强行投票。
   **数据取不到 ≠ 负面信号。**
5. **证据必须可回到原文。** 每条观测保存最短必要原文片段；只保存模型摘要的观测无效。
6. **语义判断交给 LLM，计数与规则交给代码。** 这条线要划在正确的位置：

   | 必须确定性 | 本质是语义，交给模型 |
   |---|---|
   | 证据簇去重（独立性计数） | 这条事实**属于命题的哪个维度** |
   | 立场类别计数（用声明表，见不变式 8） | |
   | common/relative 隔离规则 | |
   | 支持/反驳累计、阈值、覆盖率、时效衰减 | |

   **"这条观测是否支持这个命题"本质是语义判断。** 把它做成指标名的字符串查表，
   不会让它变得确定，只会让它变错——`hbm_market_share` 与 `hbm_share` 之间没有
   语义差别、只有命名意外，而丢掉一条份额证据是实打实的损失。真正需要防漂移的是
   计数与隔离规则，那些错了才会造成实际损失，而它们可以保持纯算术。
7. **一家公司的自述不足以支撑跨标的命题。** 我们追踪的信号几乎都是产品级/行业级的，
   单份财报既只代表自家情况，又可能选择性披露。所以命题必须**在定义时**就声明要
   交叉验证谁——下游客户、同业、竞争者各自该说什么。
8. **证人立场由命题声明，不由文档推断。** 每份财报都是公司自己的电话会，从文档里
   问"说话人是谁"永远得到"这家公司自己"，跨立场印证会结构性地永不成立。
   立场是命题的属性：定义命题时就写明"NVDA 在这条命题上是客户侧证人"。
9. **这条链路不碰 broker。** 只有 Chief 产生 `TradeDecision`，只有 Boss 放行订单。
   本系统只改变**证据**，不新增下单路径。

## 三、两类信号

| | A 类 · 共同需求 | B 类 · 相对份额 |
|---|---|---|
| 问什么 | 这个环节整体冷还是热 | 这个环节里谁在赢 |
| 例子 | HBM 供给仍紧张、需求持续扩大 | 海力士被三星反超；CXMT 量产成功 |
| 能否预先枚举 | 能（供需、capex 方向、价格趋势） | **不能**——你无法提前声明"海力士会被反超" |
| 产生方式 | 多方印证 | 从财报读出竞争位置证据 |
| 出口 | 层级景气 → 层权重上限/倾斜 | **截面因子 `moat_pricing`** → 个股权重重排 |

**关键观察**：把"HBM 供给紧张、需求扩大"这半句从两个真实信号里抽掉，剩下的
"海力士被三星反超" 和 "CXMT 量产成功" 才是真正驱动动作的部分。**A 类不产生动作，
B 类才产生动作。** 一个只做 A 类的证据系统，做得再严谨也停在决策之前。

## 四、命题的形态：维度，不是指标名

命题不是一句口号，它声明**四件事**：要看哪些维度、每个维度什么方向算支持、
**这个维度该由谁来说**、以及哪些维度能改变相对份额。

```yaml
- id: hbm_supply_tight
  kind: common
  statement: HBM 供给持续紧张、需求高于规划产能
  concepts:
    - key: supply_tightness
      desc: 供给紧张程度——售罄比例、订单能见度、交期长短
      supports_when: up
      expect_from: [SKHY, MU, "005930.KS", NVDA]
    - key: capacity_addition
      desc: 新增产能与资本开支投放节奏
      supports_when: down          # 产能大增 = 供给转松 = 反证
      expect_from: [SKHY, MU, "005930.KS"]
```

三个要点：

- **`desc` 是给模型的语义锚，不是给人看的注释。** 观测按语义归到维度上，
  `hbm_market_share` / `hbm_share` / "份额指引下修" 会落进同一个维度。
  **绝不用指标名做字符串匹配**——那样丢证据只是因为命名意外。
- **`supports_when` 逐维度声明。** 同一条命题里方向可以相反：在"供给持续紧张"下，
  交期变长支持它，产能上升却是反证。只在命题层面写一个方向，引擎会把"供给转松"
  算成"紧张的证据"——把结论算反，而且算得很自信。
- **`expect_from` 声明该由谁来说。** 这是不变式 7 的落地：单份财报只代表自家情况、
  且可能选择性披露，所以定义命题时就要写清交叉验证谁。声明之后，**沉默会显示成
  缺口而不是中性**（"三星在 capacity_addition 上本季未发声"）。

归不上任何维度的观测**照常入库**——它们正是第六·五节"未映射池"的输入。

## 四·五、三道闸

聚合器（确定性，无 LLM）按顺序过三道闸，任何一道不过就降级，不是"尽力给个结论"。

### 闸 1 — 去重：先聚簇，再计数

按 `原始出处 + 发言人 + 同一事实` 聚类。同一簇内无论多少篇文章、多少个渠道，
只算**一次**。防的是伪多源：一家公司自己的新闻稿、电话会、财报 deck 重复同一个
数字，不是三个独立证据。

### 闸 2 — 立场：三家卖方不等于三类证人

立场取自**命题声明的证人表**，不取自文档抽取（不变式 8）：

```yaml
witnesses:
  - {entity: NVDA,        stance: customer}     # 下游客户
  - {entity: SKHY,        stance: incumbent}    # 我们持有的这家
  - {entity: MU,          stance: competitor}
  - {entity: "005930.KS", stance: competitor}
```

**要求至少 2 类不同立场**才能给出确定结论；只有单一立场（哪怕十家）最高只能到
`mixed`。公司自身指引即使正式，也不能单独确认整个命题。研报/媒体/市场行为是二手
材料，可以加权重但**永远不贡献立场类别**。

### 闸 3 — common / relative 隔离（最重要）

这道闸是本设计和"朴素多家投票"的根本区别：

- **A 类（common）claim**：任何证人在任一维度上的读数都可以计入。
- **B 类（relative）claim**：必须声明 `subject`（主体，如 SKHY），并把能改变份额
  判断的维度标为 `direct: true`（份额、客户认证、ASP、毛利率）。
  **只有关于 subject 本人、且落在 direct 维度上的读数才能改变它。**
  竞争者单纯的**扩产/需求/指引上修，只计入关联的 A 类 claim，不动 B 类**。

举例，美光上调 HBM 指引，正确的记账是四条同时发生：

```
HBM 行业需求      common   → positive
美光份额          relative → positive   （美光自己的直接读数）
SK Hynix 份额     relative → 保持 unknown   ← 闸 3 拦在这里
存储设备需求      common   → positive
```

**只有出现"三星通过核心客户认证且 SK 份额指引下修"这类直接证据时，SK 的 relative
才转 contradicted。** 这正是我最初方案会犯的错误——"三星扩产 → 下调海力士"是一步
没有证据支撑的推导。

## 五、最后一公里：接到截面因子

截面模型里已经有这个因子，只是从来没有事件级证据喂它：

**`moat_pricing`（-2..+2，护城河/份额/定价权/客户集中）**，混合模式下权重 20%
（量化因子整体压到 60%、结构因子 40%）。"市占率和涨价利润被三星反超"——逐字对应
这个因子。

**当前的真实状态**：结构层的触发条件是"该层配了知识库笔记"，而整个 AI 硬件配置
**只有 L3 光互联层配了**。所以 **L5（HBM）、L4、L6 从来没跑过结构层**，三家的
`moat_pricing` 永远是空值、记 0 分、完全中性。

> 表达"海力士被三星反超"的那个因子，在 HBM 层压根没被计算过一次。

所以本设计的落点是：

```
B 类 relative claim 结论
  → 该 subject 的 moat_pricing 证据包（带原文片段）
  → structure_analyst 在 -2..+2 轴上打分（只在有证据时打分）
  → 截面复合分重排 → 建议权重反转
```

映射规则（确定性）：`supportive` → 正向证据；`contradicted` → 负向证据；
`unknown` / `mixed` → **不产生证据，`moat_pricing` 保持空值**（cohort-neutral）。
空值不等于 0 分的"中性判断"，它等于"没查过"，两者在报告里必须能区分。

同时要给 **L4 / L5 / L6 补上结构层知识库**，否则结构层对这些层继续整体跳过,
证据搬进去也没人读。

### 截面之后：三个必须一起修的断点

落到 `moat_pricing` **还不够**——截面的输出目前落在死胡同里。实施前先认清现状：

| # | 现状 | 后果 |
|---|---|---|
| 1 | 截面选股**不自动跑**（`run_cross_section` 只在 `cli.py`，`scheduler.py` 里没有），结构层还要额外加 `--structure` | 不手敲命令就永远不会重排 |
| 2 | 算出的 `SectorReview.baskets` **没有任何消费者**（全仓库只有 `cross_section.py` 自己写入） | write-only，白算 |
| 3 | Chief 的行业块**不渲染 basket** | Chief 看到的是 LLM 给的 stance，不是确定性因子模型的结论 |

所以第三阶段必须一并做：**截面纳入周度调度**（跟行业评审一起跑，默认带结构层）
+ **basket 接进 Chief**。

**接进 Chief 的形态：只给分歧与依据，不给权重数字。**

```
截面（L5）  复合排名与纯量化排名的分歧：
  三星    量化第3 → 复合第1   依据：HBM4 通过核心客户认证 · 涨价15% · 份额+6pt
  海力士  量化第1 → 复合第2   依据：份额指引下修 -5pt · HBM 毛利率环比 -3pt
```

**刻意不把"建议权重 13% / 9%"写进 Chief 上下文。** 因子模型给的是相对关系和依据，
Chief 仍须自己决定仓位——不变式是"Chief 是唯一决策者"，把确定性模型的权重数字直接
递过去，Chief 大概率照抄，等于决策权悄悄转移给了一个没人为它负责的模型。

### 决策桌上的样子

```
## L5 芯片制造 · 截面重排

层级状态(A类)   HBM 供给紧张  confirmed  4/5 已报  证人立场 3 类
                 需求端持续扩大 → 层权重上限维持 30%

层内位置(B类)   三星    moat_pricing   0.0 → +1.5
                        依据：HBM4 通过核心客户认证 · 涨价 15% 落地 · 份额 +6pt
                 海力士  moat_pricing  +1.0 → -0.5
                        依据：份额指引下修 -5pt · HBM 毛利率环比 -3pt
                 美光    moat_pricing   0.0 →  0.0（扩产读数只计入 A 类，未动份额）

截面复合重排     三星    量化第3 → 复合第1    建议权重  8% → 13%
                 海力士  量化第1 → 复合第2    建议权重 14% →  9%
```

## 六、数据模型

**两张表**，全部 additive migration，不动现有表：

| 表 | 存什么 |
|---|---|
| `evidence_observations` | 一次观测：来源文档 / 实体 / 指标原名 / **归属维度**（语义链接，空=未映射）/ 期间 / 方向 / **原文片段** / 观测类型（已实现·指引·对手方陈述·研究·媒体） |
| `claim_assessments` | 聚合快照：claim / as_of / verdict / 支持与反驳分数分列 / 证据簇数 / 立场类别数 / 引用的观测 |

**主题不建注册表。** 命题就写在 `config/sectors/ai_hardware.yaml` 每层下的 `claims:`
条目里，人工维护、你点头才加。复用现成的 L1-L6 分层和 `config/risk.yaml` 的
instrument registry（SKHY / HY9H / 000660.KS 归一到同一经济实体的能力**已经存在**），
不新造第四个配置真源。

配置形态见第四节。相对份额命题多两样东西——`subject` 和 `direct: true` 维度：

```yaml
      - id: sk_hbm_share
        kind: relative
        subject: SKHY
        statement: SK Hynix 维持核心客户 HBM 领先份额与定价权
        concepts:
          - {key: hbm_share, desc: HBM 份额/供货占比及其指引, supports_when: up,
             direct: true, expect_from: [SKHY, MU, "005930.KS", NVDA]}
          - {key: customer_qualification, desc: 核心客户认证进展（谁通过、谁被替代）,
             supports_when: down, direct: true, expect_from: [NVDA, "005930.KS", MU]}
          - {key: hbm_pricing, desc: HBM 价格/ASP 与毛利率走向, supports_when: up,
             direct: true, expect_from: [SKHY, MU]}
        witnesses:
          - {entity: SKHY, stance: incumbent}
          - {entity: MU, stance: competitor}
          - {entity: "005930.KS", stance: competitor}
          - {entity: NVDA, stance: customer}
        falsifiers: [竞争对手通过核心客户认证且 SK 份额指引下修]
```

- `direct: true` 是闸 3 的执行依据：只有落在这些维度、且关于 `subject` 本人的读数
  才能改变相对份额判断。
- `horizon` 让"2027 年前供不应求"和"本季供不应求"成为不同命题。**超出时效的观测
  衰减回 unknown，不永久有效**；命题过期后进入待复核，不静默沿用。
- **覆盖率随结论一起呈现，且沉默要点名**：结论带"应到证人 / 已到证人"，并列出
  **本期未发声的证人**。`supportive 4/5` 与 `supportive 1/5` 必须一眼可分——否则
  你不知道一个结论建立在几分
  之几的证据上。

## 六·五、涌现命题：agent 归纳，你采纳

前面几节回答的是"**验证你已经声明的命题**"。但真实世界里最有价值的信号常常是你还
没想到去声明的那一类，例如：

> AI 数据中心的增量瓶颈正从存储转向光互联/InP 供应。

这类命题有两个特点，让它无法用前面的机制覆盖：**跨层**（不属于 L5 也不属于 L3），
且**涌现**（不是预先声明的，是从数据里冒出来的）。

**不能用确定性检测器解决。** 写一个"跨层紧张度环比排序"只能抓"瓶颈迁移"这一个模式；
下一个信号可能是"客户结构从云厂转向主权 AI"或"技术替代快过预期"，枚举式检测器一个
都抓不到。**用有限的检测器去覆盖开放集合，方向本身就是错的。**

### 机制：证据驱动，不是日历驱动

| 步骤 | 做什么 |
|---|---|
| **未映射池** | 每条观测先与已声明 claim 匹配；**匹配不上的落进未映射池**（带实体/指标/方向/原文）。这些就是"系统已掌握但尚无归属"的信息 |
| **触发** | **不设 cron。** 未映射池积累到足够分量时触发一次归纳（N 条观测 × ≥M 个不同实体 × 指标族或方向上呈现结构）。**触发条件确定性，归纳交给 LLM** |
| **产出** | 一张**待确认命题卡**给你。不进因子、不进 Chief、不启动任何监控任务 |
| **采纳** | 你点头 → 写入配置成为正式 claim；拒绝 → 记录并冷却，同一命题不得换个说法反复提 |

这就是"不定期"的含义：由信息的积累驱动，不由时间驱动。

### 待确认命题卡

```
待确认命题（由 14 条未映射观测积累触发）

  「AI 数据中心的增量瓶颈正从存储转向光互联/InP 供应」

  支撑观测（均可点回原文）
    COHR   1.6T 光模块交期延长至 26 周       [电话会]
    LITE   InP 关键组件售罄、缺口 >30%       [财报]
    AXT    InP 衬底扩产，良率爬坡慢于计划     [电话会]
    MU     HBM 供给紧张度环比缓解            [指引]
    SKHY   HBM 扩产进度提前                  [指引]

  建议的 claim 形态
    kind: common · 跨 L5→L3 · direct_metrics: [交期, 缺口率, 良率]
    证人立场：供给方×3 / 需求方×0   ⚠️ 立场单一，需求侧尚无证据

  → 采纳 / 拒绝 / 继续观察
```

### 防事后编故事（必须有）

触发这次归纳的那批观测**冻结为 discovery evidence**：

```yaml
discovery_evidence: true
eligible_for_confirmation: false
```

命题被采纳后，它的 verdict **只能由采纳时点之后的新证据**开始积累。发现它的材料只
说明"为什么值得看"，不能同时充当"它是对的"的证据。

> 这条是本设计唯一从 codex 方案（§8.1）保留的发现侧机制。之所以必须有：一旦 agent
> 能提出命题，"用发现它的那批材料反过来证明它"是必然会发生的错误，只能结构性地堵。

### 权限边界

| | agent 能 | agent 不能 |
|---|---|---|
| 归纳出新命题 | ✅ 并呈报给你 | ❌ 自己写进配置 |
| 影响截面因子 | ❌ | 只有你采纳的命题才有资格 |

**坐标系依然只有你能扩。** 这是截面因子历史可比的前提，也是"agent 提出 ≠ agent 决定"
这条线的落点。因为归纳的产出只是一张给人看的卡、不会自动启动持续监控任务，**不存在
主题爆炸问题**——所以不需要准入控制器、信息价值排序、多级预算这类治理机制。

## 七、四阶段实施与验收

每阶段独立提交、独立验收。**上一阶段未通过不进入下一阶段。** 任何阶段都不改变
下单路径、审批流程或风控参数。

### 阶段一：证据表 + 观测抽取　✅ 已完成

建表、抽取角色 `evidence_observer`（便宜模型档）、只在观察名单财报后触发。
**只写库，不影响任何现有输出。**

**测试** `tests/test_chain_evidence.py`：

| 用例 | 断言 |
|---|---|
| 幂等 | 同一文档/实体/指标/期间重跑，库里只有一条（确定性 id） |
| 原文片段必填 | 缺 span 的观测被拒绝入库，不静默落盘 |
| 类型不混 | 「本季 HBM 收入为 X」记为 `reported_actual`；「明年产能已售罄」记为 `guidance`；两者不可互相冒充 |
| 立场必填 | `stance` 不在枚举内的观测被拒绝 |
| 抽取失败 | 保存失败状态与原因，**不用默认值填充**，不生成假观测 |
| 提示注入 | 第三方文本里的指令不改变抽取任务 |

**验收**：观察名单某次真实财报跑完，每条观测都能点回原文；现有全量测试不回归。

### 阶段二：聚合三道闸　✅ 已完成

实现 `corroborate()`，参数（阈值、衰减、立场要求）全部走配置。

**测试** `tests/test_chain_corroborate.py`：

| 闸 | 用例 | 断言 |
|---|---|---|
| 去重 | 10 篇转载同一原始报道 | 只计 1 个证据簇 |
| 去重 | 公司新闻稿 + 电话会 + deck 同一数字 | 只计 1 个证据簇 |
| 立场 | 3 家卖方同向 | 最高 `mixed`，**不能** `confirmed` |
| 立场 | 客户 + 供应商同向 | 可以 `confirmed` |
| **隔离** | **美光上调 HBM 指引（仅扩产/需求读数）** | **行业需求 `common=supportive`；美光 `relative=supportive`；SK 份额保持 `unknown`——不得为 negative** |
| 隔离 | 三星通过核心客户认证 + SK 份额指引下修 | SK `relative` 才转 `contradicted` |
| 新鲜度 | 观测落在 claim `horizon` 之外 | 退回 `unknown`，不永久有效 |
| 覆盖率 | 5 个证人只到 1 个 | 结论带 `1/5 已报`，与 `4/5 已报` 在输出上可区分 |
| 可达性 | 关键指标取不到 | claim 保持 `unknown`；**断言不被解释成负面** |
| 反证不被净额掩盖 | 支持 3 条、反驳 2 条 | 两侧分数分别保留，不只显示净值 |
| 极性 | 同一 claim 下"交期↑"与"产能↑" | 前者计支持、后者计反驳，不被同向合并 |
| **语义链接** | 抽出 `hbm_market_share`，命题维度叫 `hbm_share` | **必须归到同一维度**，不得因命名差异丢失 |
| 立场来源 | 每份文档都是公司自述（抽取值恒为 incumbent） | 立场取自命题声明的证人表，跨立场印证仍能成立 |
| 沉默即缺口 | 声明的证人本期未发声 | 结论里点名该证人，不当作中性 |
| 发现材料隔离 | 观测被标记 discovery_evidence | 不得计入该 claim 的 verdict |

**验收**：上表全绿。特别是隔离那两条——它们是这套设计存在的理由。

### 阶段三：接 moat_pricing + 打通截面到 Chief

给 L4/L5/L6 补结构层知识库；`structure.assess()` 增加证据包入参；**截面纳入周度调度**；
**basket 分歧接进 Chief**；feature flag 控制。

**测试** `tests/test_chain_to_cross_section.py`：

| 用例 | 断言 |
|---|---|
| 证据包送达 | relative 结论生成的证据包出现在 structure_analyst 的上下文里 |
| 重排生效 | 给定 moat_pricing 一升一降，复合排名与建议权重按预期反转 |
| **回归保护** | **feature flag 关闭时，截面输出与当前系统逐字一致** |
| common 不越界 | A 类结论只影响层级景气，**不改任何 moat_pricing** |
| 空值语义 | 证据不足时 `moat_pricing` 保持空值（cohort-neutral），与"评过分且为 0"可区分 |
| 自动调度 | 周度评审跑完后截面自动跑且带结构层，不需手敲命令 |
| **进 Chief 但不给权重** | Chief 上下文出现"量化第3 → 复合第1 + 依据"，**断言不出现建议权重百分比** |

**端到端 fixture**（不打网络、不碰 Obsidian、不碰 IBKR）：

- **HBM-保持**：行业需求正面 + 无直接份额证据 → 断言**不产生**减仓 SK 的权重变化。
  这是最容易犯错的场景，必须常驻。
- **HBM-反超**：有直接份额证据 → 断言 SK `moat_pricing` 下调、三星上调、截面权重反转，
  且 Chief 上下文能看到这个分歧。

**验收**：两个 fixture 全绿；flag 关闭时与当前系统零差异。

### 阶段四：涌现命题归纳

未映射池 + 证据驱动触发 + 待确认命题卡 + discovery evidence 冻结。

**测试** `tests/test_chain_induction.py`：

| 用例 | 断言 |
|---|---|
| 未映射入池 | 匹配不上任何已声明 claim 的观测进入未映射池，且不影响任何 claim 的 verdict |
| 触发是确定性的 | 未达阈值不触发归纳（不调 LLM）；达阈值触发且只触发一次 |
| **非日历驱动** | **纯时间流逝不触发归纳**——只有新观测积累才触发 |
| **防事后编故事** | **触发归纳的观测被冻结；命题采纳后，这些观测不得计入 verdict** |
| 采纳前零影响 | 待确认命题不进因子、不进 Chief、不启动任何监控任务 |
| 拒绝有冷却 | 被拒绝的命题在冷却期内换个说法重提会被识别并抑制 |
| 立场缺口显式 | 卡片标注证人立场分布（如"供给方×3 / 需求方×0"），不隐藏单一立场 |

**端到端 fixture**：**光互联-瓶颈迁移**——喂入跨 L5/L3 的未映射观测，断言归纳出跨层
命题卡；随后断言**仅凭这批发现材料无法让该命题达到 supportive**，必须有采纳后的新证据。

**验收**：上表全绿；尤其"防事后编故事"和"非日历驱动"两条——它们分别是这个阶段的
正确性底线和你要的"不定期"的落点。

## 八、边界（明确不做）

- **不建知识图谱。** 不新增节点/边类型体系——复用现成的 L1-L6 分层与 instrument registry。
- **不建主题注册表、不做主题生命周期状态机。** 命题写在 sector 配置里，人工维护。
- **Agent 可以归纳新命题，但不能自己启用。** 见第六·五节：归纳的产出是一张给你看的
  待确认卡，不进因子、不进 Chief、不启动任何持续监控任务；**你采纳后才成为正式 claim**。
  坐标系只有你能扩——这是截面因子历史可比的前提。
  （也因为归纳只产卡、不自动起任务，**不存在主题爆炸**，所以不需要准入控制器、
  信息价值排序、多级预算这类治理机制。）
- **不用固定检测器去猜涌现命题。** 写死"跨层紧张度环比排序"只能抓瓶颈迁移一种模式，
  抓不到客户结构变化、技术替代提速等等。开放集合不能用枚举覆盖。
- **不让证据系统改硬风控。** 六层限额不受本系统影响。
- **不表达非上市实体的建仓侧。** CXMT 这类未上市实体只作为**减仓侧信号**存在
  （下调整个 cohort 的定价权），不尝试映射可交易代理——代理选错会把对的信号做成
  错的交易。
- **不用股价证明基本面。** 价格是市场行为观测，不能单独确认供需命题。

## 十、与既有系统的关系

- **PEAD** 是时间序列/事件信号（一只票的财报预期差，回答"何时动"）；**截面因子**
  回答"同层里买谁、买多少"；**本系统**给截面因子提供它一直缺的竞争位置证据。
- **行业评审**（`docs/SECTOR_ANALYST.md`）继续产出周度分层景气；A 类 claim 的印证
  状态是它的事件级补充，不替代它。
- **风控**（`docs/RISK_SYSTEM.md`）不读本系统的输出。层权重上限仍由 `config/risk.yaml`
  的 `sector_layer_caps` 决定。
